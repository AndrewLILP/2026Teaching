Analysing data

Every game and app you build creates data. This unit teaches you to turn that data into information someone can act on: asking the right question, cleaning and checking the data, summarising it in a spreadsheet and a database, and presenting it honestly and safely.

About this unit

The unit runs for one term: 25 lessons of 55 minutes. Most lessons are discussion-based. You'll look closely at something that already exists, talk about it with a partner, then apply the idea yourself.

Every lesson has the same shape, so you always know where you are:

  • learning intentions and a hook question
  • vocabulary flip-cards
  • an analysis activity before any new theory
  • tasks at three levels: Foundation, Core and Extension
  • six checkpoint questions and one exam-style question with a marking guide
  • a reflection that saves on this device.
Tools: a spreadsheet (from Lesson 14) and a browser-based SQLite database (Lessons 22–23). Nothing needs to be installed.

Datasets

Each project has two versions of its data:

  • Raw: what the system actually recorded, including mistakes, duplicates and test records. You'll clean these yourself in Lesson 14.
  • Clean: the checked version. Use it if you fall behind or want to check your own cleaning.

For the database lessons, analysing-data.db holds every clean table, plus the Canteen Click menu.

Outlier or error?

Not every strange value is a mistake

Every raw file contains errors that should be removed, and at least one strange but genuine record that should be kept. Telling the two apart is one of the most important skills in this unit.

Think about it: a player takes 24 minutes to finish a level that usually takes 2. Mistake, or real? What would you check before deciding?

For teachers

Unit at a glance

Focus area: Enterprise information systems: Analysing data (single focus, ≈ 23 hours). Every dot point in the focus area is covered.

Timing: 10 weeks at 5 lessons per fortnight. Week 10 has two lessons, which leaves room for one catch-up lesson.

Assessment: formative. Checkpoint results and reflections are stored in each student's browser only (no server, no names). Ask students to show their progress list, or screenshot it, if you want evidence.

Data: all five datasets are generated by data/make_datasets.py from a fixed random seed, so re-running it gives identical files.
