Where does the data go?

Last lesson you saw that information comes from processing data. But before data can be processed, it has to be captured, saved and usually sent somewhere. Today you'll follow data through five stages (input, storage, transmission, processing and output) in each of our five projects.

Identifying & defining

Teaching advice

Timing: hook 4 min · vocabulary 5 min · follow one order 10 min · five stages 8 min · comparison table 10 min · risks and Wi-Fi case 6 min · tasks 5 min · checkpoint and exam question 5 min · reflection 2 min.

Discussion focus: students often merge storage and transmission ("it goes to the cloud"). Push for precision: where is it saved, and how does it travel?

Optional prop: a phone with any food-ordering app. Walk through an order and ask where each step's data lives.

Learning intentions

By the end of this lesson I can:

  • describe the inputs, storage, transmission, processes and outputs in a data analysis
  • compare where and how data is stored and transmitted in different systems
  • identify a security risk at the storage and transmission stages.
Success criteria: I can complete a five-stage table for at least two of the five projects, and name one way the data could be put at risk while it is stored or sent.

One run, three time scales

A player on a Steam Deck ends a run on Level 3 of Coin Run 3D. The game writes one record:

One record R129,P-2EDY,3,17,40,710.8,8,N,SteamDeck

Talk with the person next to you. What happens to this record in the next second? The next day? The next week? Where is it, and who can see it at each point?

Next second: the game saves the record to a file on the Steam Deck's own storage. Only that device has it.

Next day: when the Deck is online, the game uploads the file to the developer's server over an encrypted connection. Now the record is in two places.

Next week: the developer combines it with every other run and calculates completion rates per level and platform. The record has become part of information in a playtest report.

Interesting detail: this run lasted 710.8 seconds and ended with 8 deaths and no completion. Keep it in mind. Long, failed Level 3 runs on Steam Deck will matter later in the unit.

Follow one order

Before we name the stages, take apart a system you already know. Here is everything that happens to one Canteen Click order, order O001, from the moment a Year 9 student taps "Order". The steps are in order. Decide which stage each step belongs to.

  1. 1. The student taps Sushi roll, chooses Lunch and taps "Order".

  2. 2. The app sends the order over the school Wi-Fi to the canteen's server.

  3. 3. The server saves the order as a new row in the orders database.

  4. 4. The order appears on the kitchen screen under "Lunch".

  5. 5. On Friday afternoon, the server counts every order by item and by day.

  6. 6. The manager reads a weekly report: "176 orders, busiest day Friday".

Discuss · pairs · 4 min

Look closer at the journey

  1. Steps 4 and 6 are both outputs. How are they different? Who is each one for, and how much processing happened first?
  2. The order exists in at least two places by step 3. Where are they?
  3. Which step would fail if the school Wi-Fi went down? What would the student see?

The five stages

Every data system, from a coin counter in a game to a national census, moves data through the same five stages. The stages don't always happen in this order, and some happen more than once: data is often stored, sent, then stored again.

  1. 1

    Input

    Data is captured. A person types or taps, or a sensor measures something.

    Example A StepUp watch counts steps and measures heart rate during a walk.

  2. 2

    Storage

    Data is saved so it isn't lost: locally on the device, in a database, or in the cloud.

    Example Cave of Echoes appends one row to sessions.csv when a session ends.

    Data is most valuable here, and so it's also most at risk here. A lost laptop or a leaked database exposes every record at once.

  3. 3

    Transmission

    Data moves between devices: by Bluetooth, Wi-Fi, mobile data or a cable.

    Example Coin Run 3D uploads run records from the Steam Deck to the developer's server.

    Data in transit can be intercepted. Encryption (HTTPS) makes intercepted data unreadable.

  4. 4

    Process

    Data is sorted, counted, averaged, grouped or compared. This is where analysis happens.

    Example Pixel Pockets groups failed attempts by the x position where they ended.

  5. 5

    Output

    The result is shown to a person in a form they can use: a chart, a list, a notification, a report.

    Example Canteen Click shows the manager a weekly sales report.

We do · whole class · 5 min

The fifth project, Cave of Echoes, is a Python text adventure that runs in a terminal. When a session ends, it uses Python's csv module to add one row to sessions.csv in the game's folder. Together, complete its five stages in your notebook.

One stage is tricky. Is there any transmission at all?

Input: commands typed with input(); the game counts valid and invalid commands and the rooms visited.

Storage: one row appended to sessions.csv on the local computer.

Transmission: none while the game runs. The data only moves if someone copies, emails or uploads the file. "No transmission" is a valid answer, and it's a design choice: it keeps the data private but means the developer only sees data that players choose to share.

Process: compare the ending (Escaped, Lost, Quit) with the number of invalid commands.

Output: a table or chart in the developer's notes, used to decide whether to improve the command parser.

What could go wrong?

Each stage has its own risks. Storage and transmission are where data is most often lost or exposed.

When the Wi-Fi drops

Case study

Lunch rush, no network

It's Friday, the busiest day of the week for Canteen Click. Five minutes before lunch, the school Wi-Fi goes down. Students keep tapping "Order", but the app can't reach the server.

The development team has three options. A: show an error and throw the order away. B: save the order on the phone and send it automatically once the network is back. C: switch to paper orders until the Wi-Fi returns.

Discuss: Which option would you choose? Explain your choice using the words storage and transmission. What new problem does your option create? (Hint: what if the kitchen has already sold out?)

Exam-style question

Short answer 4 marks

StepUp is a fitness app. A smartwatch measures steps and heart rate during a workout. The watch sends this data to the user's phone, which saves it and later syncs it to a cloud database.

Question: Describe how StepUp's data is stored and transmitted. Identify one security risk for storage and one for transmission.

Write your answer in your notebook before opening the marking guide.

Marking guide
CriteriaMarks
Correctly describes storage AND transmission in StepUp, and identifies a relevant risk for each4
Describes storage and transmission with one relevant risk, OR describes one stage well with risks for both3
Describes storage or transmission, with some reference to risk2
Provides some relevant information1

Sample answer: StepUp stores data in two places: first locally on the user's phone, then in a cloud database. It is transmitted twice: from the watch to the phone by Bluetooth, and from the phone to the cloud over the internet. A storage risk is that the phone is lost or stolen, exposing the user's heart rate history if the phone isn't locked and encrypted. A transmission risk is that the sync is intercepted on public Wi-Fi if it isn't sent over an encrypted HTTPS connection.

Common error: writing "it's stored in the cloud" without naming the phone as a storage location, or calling the cloud upload "storage" instead of transmission.
