Lesson 3 of 3 · Enterprise information systems: Analysing data

Runoff in a database

Same river data, different tool. This time it is stored as two linked tables in a relational database, and you ask questions in SQL. You’ll find out what a database does better than a spreadsheet, and use it to catch three data problems hiding in nearly 2,000 rows.

CT5-DAT-01 CT5-DAT-02 CT5-THI-01 CT5-COM-01

Learning intentions

We are learning to:

  • model data as related tables linked by keys
  • write SQL queries to select, group and join data
  • validate and correct data with queries
  • compare a spreadsheet and a database for the same job

Success criteria

I can:

  • identify the primary key and foreign key that link two tables
  • write a query using WHERE, ORDER BY and GROUP BY
  • join two tables to answer a question neither table answers alone
  • find a duplicate, an impossible value and a missing value, and fix them with UPDATE or DELETE
Worked example 4 min I do

Why a database?

In Lesson 2, every one of the 1,842 sample rows repeated the site’s full name and river. That is a flat file. If a site name changed, you would have to fix it in more than 200 places, and miss some.

A relational database stores each fact once and links tables with a key. Booklet p. 8

Count and group

GROUP BY does what a pivot table did in Lesson 2: it squashes many rows into one row per group.

JOIN 6 min I do We do

Join two tables

Which river carries the most sediment on average? The sediment is in samples; the river name is in sites. Neither table can answer alone. A JOIN matches rows on the key, like the lookup in Lesson 2.

Read the join aloud

“Take every sample, find the site with the same site_id, keep both rows side by side, then group by river.” Try changing ss_mgl to din_mgl: which river has the most fertiliser nitrogen?

Validate and correct 7 min We do

Find and fix three bad records

Three problems are hiding in samples. Find each one with a query, then fix it.

That row still has a valid sediment value. NULL honestly records “not measured”, and AVG() skips NULLs automatically. Deleting the row would throw away good data. The negative sediment value is different: it is impossible, so it becomes NULL too, and you note why. A database can also stop bad data at the door: a rule like CHECK (ss_mgl >= 0) would have rejected it on entry.

How this lesson is graded

Evidence sits against developing computing solutions using computational, design and systems thinking (CT5-THI-01) and selecting data, media and processes to communicate information (CT5-DAT-02, CT5-COM-01).

A

“Develops highly effective computing solutions…” and “…effectively communicate information”. Today: concise queries that answer every question, including the single-query decade comparison, and a justified choice of tool.

B

“Develops effective computing solutions…” and “…communicate appropriate information”. Today: correct GROUP BY and JOIN queries, and all three data problems found and fixed.

C

“Develops sound computing solutions…” and “selects appropriate data, media and processes to communicate information”. Today: working WHERE, ORDER BY and GROUP BY queries, and the data problems found.

D

“Develops basic computing solutions…” and “uses data to communicate basic information”. Today: you change example queries to answer simple questions.

E

“Uses data to communicate information in a very limited way”. Today: with support, you run queries and read the results. The thinking strand has no Grade E descriptor, so only the communication strand is quoted. “Today” lines describe evidence for this lesson only.
