Photo mode hook and camera

Today the design becomes code. You'll add one script to your game that switches photo mode on and off, freezes the world, and gives the player a camera they can move, but only so far. Your own player controller connects to it with a single method call: the hook.

Producing & implementing
Last lesson: you designed the journal's data, wrote CapturePhoto in pseudocode and met the guard pattern: checks that can stop an algorithm go at the top. Today's script uses the guard pattern three times. See if you can spot them all.

Teaching advice

Timing: recap and vocabulary 5 min · analyse states 5 min · hook design and pseudocode 8 min · code walkthrough 10 min · setup and connect 15 min · tests and checkpoint 7 min.

Before class: students back up or commit their projects. Install the Input System package (Window → Package Manager → Unity Registry). When Unity asks to switch input backends, choose Both under Project Settings → Player → Active Input Handling. This keeps students' existing Input.GetAxis code working alongside the new script.

Design choice: the camera is plain C# rather than Cinemachine, so every line can be traced and it works with any camera setup. Students already using Cinemachine add their CinemachineBrain to the script's disable list. Mouse look is added in Lesson 7. Today, look uses the right stick or arrow keys.

Learning intentions

By the end of this lesson I can:

  • translate pseudocode into C# methods that use guard clauses
  • explain why photo mode uses a hook instead of checking the player's state itself
  • connect photo mode to my own controller and test that it meets requirement R1.
Success criteria: in my game, photo mode opens only while on foot, freezes the world, limits the camera to 4 metres, and puts everything back exactly as it was on exit.

Designing the hook

There are two ways photo mode could know whether it's allowed to open:

DesignHow it worksProblem
A. Photo mode checksPhoto mode looks at the car script, the menu script, the dialogue script and so on, every frame.It has to know about every system in your game, so it can't be shared, and every new state means editing it. This is high coupling.
B. The game tells it (hook)Your code calls SetAvailable(true) when the player starts walking and SetAvailable(false) when they stop.None for us. Photo mode knows nothing about cars or menus, so the same script works in every student's game. This is low coupling.

We use design B. The method SetAvailable is the hook: the one point where your game and the photo mode connect.

Planning

Pseudocode first

Four short algorithms make up the switching logic. Find the guard clauses before reading on.

NSW pseudocode · SetAvailable and TogglePhotoMode

1   BEGIN SetAvailable(available)
2       SET isAvailable TO available
3       IF isAvailable = FALSE AND isActive = TRUE THEN
4           ExitPhotoMode()
5       ENDIF
6   END SetAvailable

7   BEGIN TogglePhotoMode
8       IF isAvailable = FALSE THEN
9           RETURN
10      ENDIF
11      IF isActive = TRUE THEN
12          ExitPhotoMode()
13      ELSE
14          EnterPhotoMode()
15      ENDIF
16  END TogglePhotoMode

NSW pseudocode · EnterPhotoMode and ExitPhotoMode

1   BEGIN EnterPhotoMode
2       SET isActive TO TRUE
3       SAVE camera position and rotation
4       DISABLE player movement and camera follow
5       HIDE hud
6       SET savedTimeScale TO timeScale
7       SET timeScale TO 0
8   END EnterPhotoMode

9   BEGIN ExitPhotoMode
10      SET isActive TO FALSE
11      SET timeScale TO savedTimeScale
12      RESTORE camera position and rotation
13      SHOW hud
14      ENABLE player movement and camera follow
15  END ExitPhotoMode

Exit undoes Enter in reverse order, like taking off a jacket after a backpack. Undo steps in reverse and nothing gets tangled.

Producing

Into C#

Each C# method matches one pseudocode algorithm. Work through the steps, then compare the full script at the end.

1The hook
// THE HOOK: your own player code calls this.
public void SetAvailable(bool available)
{
    isAvailable = available;
    if (!isAvailable && IsActive)
    {
        ExitPhotoMode();   // forced out, e.g. a cutscene starts
    }
}
public means other scripts can call it, which is the whole point of a hook. Apart from reading IsActive, everything else in the script is private, so no other code can accidentally switch photo mode on.
2Toggle with a guard clause
private void OnToggle(InputAction.CallbackContext context)
{
    if (!isAvailable) return;            // guard clause

    if (IsActive) ExitPhotoMode();
    else EnterPhotoMode();
}
The Input System calls OnToggle when the toggle button is pressed. The first line is the guard clause: !isAvailable means "not available". Compare it with pseudocode lines 8–10.
3Entering photo mode
private void EnterPhotoMode()
{
    IsActive = true;

    savedPosition = cameraTransform.position;
    savedRotation = cameraTransform.rotation;

    foreach (Behaviour script in disableWhileActive)
    {
        script.enabled = false;
    }
    if (hud != null) hud.SetActive(false);

    offset = Vector3.ClampMagnitude(cameraTransform.position - pivot.position, maxDistance);
    yaw = cameraTransform.eulerAngles.y;
    pitch = NormaliseAngle(cameraTransform.eulerAngles.x);

    savedTimeScale = Time.timeScale;
    Time.timeScale = 0f;                 // freeze the world
}
disableWhileActive is an array you fill in the Inspector with your own movement and camera scripts. The foreach loop switches each one off, so the script works no matter how your controller is built. The last line freezes the world: animals, water and other characters stop while the player frames the shot.
4Exiting photo mode
private void ExitPhotoMode()
{
    IsActive = false;
    Time.timeScale = savedTimeScale;

    cameraTransform.SetPositionAndRotation(savedPosition, savedRotation);
    if (hud != null) hud.SetActive(true);

    foreach (Behaviour script in disableWhileActive)
    {
        script.enabled = true;
    }
}
Everything Enter changed is put back in reverse order. Restoring savedTimeScale instead of writing 1f means photo mode won't break a game that was already in slow motion.

The photo camera

While photo mode is active, the camera turns with the right stick (or arrow keys) and moves with the left stick (or WASD). It can't move more than maxDistance metres from the hiker. This stops players flying through cliffs or seeing parts of the map that aren't finished.

NSW pseudocode · UpdatePhotoCamera (runs every frame)

1   BEGIN UpdatePhotoCamera
2       IF isActive = FALSE THEN
3           RETURN
4       ENDIF
5       SET dt TO unscaled time since last frame
6       SET yaw TO yaw + lookX × lookSpeed × dt
7       SET pitch TO pitch − lookY × lookSpeed × dt
8       SET pitch TO Clamp(pitch, minPitch, maxPitch)
9       SET offset TO offset + movement in the direction the camera faces
10      SET offset TO ClampLength(offset, maxDistance)
11      SET camera position TO pivot + offset
12  END UpdatePhotoCamera
5LateUpdate: moving the camera
private void LateUpdate()
{
    if (!IsActive) return;               // guard clause

    float dt = Time.unscaledDeltaTime;   // keeps ticking while time is frozen

    Vector2 look = lookAction.ReadValue<Vector2>();
    yaw += look.x * lookSpeed * dt;
    pitch -= look.y * lookSpeed * dt;
    pitch = Mathf.Clamp(pitch, minPitch, maxPitch);
    Quaternion rotation = Quaternion.Euler(pitch, yaw, 0f);

    Vector2 move = moveAction.ReadValue<Vector2>();
    Vector3 step = rotation * new Vector3(move.x, 0f, move.y) * moveSpeed * dt;
    offset = Vector3.ClampMagnitude(offset + step, maxDistance);

    cameraTransform.SetPositionAndRotation(pivot.position + offset, rotation);
}
LateUpdate runs after all other updates each frame, so nothing else moves the camera after us. Vector3.ClampMagnitude keeps the direction of offset but shortens it to at most maxDistance. That one line is the invisible wall.

Desk check: the invisible wall

Test values: maxDistance = 4, dt = 0.02 s (50 frames per second), lookSpeed = 90, maxPitch = 70. The camera starts 3.8 m straight behind the pivot, the player pushes forward, and each frame moves 0.5 m.

Bug detective

The frozen camera

A classmate's photo mode opens, the HUD disappears and the world freezes. But the camera won't move at all, whatever they press. Their input works in other scenes. Here is the start of their LateUpdate:

private void LateUpdate()
{
    if (!IsActive) return;
    float dt = Time.deltaTime;
    Vector2 look = lookAction.ReadValue<Vector2>();
    yaw += look.x * lookSpeed * dt;
Time.deltaTime is scaled by Time.timeScale. Photo mode set timeScale to 0, so deltaTime is 0 every frame. Anything multiplied by 0 is 0, so the camera never moves. The fix is Time.unscaledDeltaTime, which measures real time and keeps ticking while the world is frozen.
Producing

Connect your controller

Setup · follow along · 8 min

  1. Create a script called PhotoModeController and paste in the full script below.
  2. Create an empty GameObject called PhotoMode and add the script. The default controls fill in automatically: P or gamepad Y to toggle, WASD or left stick to move, arrows or right stick to look.
  3. Make an empty child of your player at head height called PhotoPivot.
  4. Drag in the references: your main camera to Camera Transform, PhotoPivot to Pivot, your HUD canvas to Hud.
  5. Add your movement script and any camera-follow script (including CinemachineBrain if you use it) to Disable While Active.
// Recommended filename: PhotoModeController.cs
using UnityEngine;
using UnityEngine.InputSystem;

public class PhotoModeController : MonoBehaviour
{
    [Header("Input (defaults are set when you add the component)")]
    [SerializeField] private InputAction toggleAction;
    [SerializeField] private InputAction moveAction;
    [SerializeField] private InputAction lookAction;

    [Header("Scene references")]
    [SerializeField] private Transform cameraTransform;   // your main camera
    [SerializeField] private Transform pivot;             // an empty object at the hiker's head
    [SerializeField] private GameObject hud;              // your HUD canvas
    [SerializeField] private Behaviour[] disableWhileActive; // movement and camera-follow scripts

    [Header("Camera limits")]
    [SerializeField] private float maxDistance = 4f;      // metres from the pivot
    [SerializeField] private float moveSpeed = 2f;        // metres per second
    [SerializeField] private float lookSpeed = 90f;       // degrees per second
    [SerializeField] private float minPitch = -60f;
    [SerializeField] private float maxPitch = 70f;

    public bool IsActive { get; private set; }

    private bool isAvailable;
    private Vector3 offset;
    private float yaw;
    private float pitch;
    private Vector3 savedPosition;
    private Quaternion savedRotation;
    private float savedTimeScale = 1f;

    // Runs when the component is first added: fills in default controls.
    private void Reset()
    {
        toggleAction = new InputAction("TogglePhotoMode", InputActionType.Button);
        toggleAction.AddBinding("<Keyboard>/p");
        toggleAction.AddBinding("<Gamepad>/buttonNorth");

        moveAction = new InputAction("PhotoMove", InputActionType.Value, expectedControlType: "Vector2");
        moveAction.AddCompositeBinding("2DVector")
            .With("Up", "<Keyboard>/w")
            .With("Down", "<Keyboard>/s")
            .With("Left", "<Keyboard>/a")
            .With("Right", "<Keyboard>/d");
        moveAction.AddBinding("<Gamepad>/leftStick");

        lookAction = new InputAction("PhotoLook", InputActionType.Value, expectedControlType: "Vector2");
        lookAction.AddBinding("<Gamepad>/rightStick");
        lookAction.AddCompositeBinding("2DVector")
            .With("Up", "<Keyboard>/upArrow")
            .With("Down", "<Keyboard>/downArrow")
            .With("Left", "<Keyboard>/leftArrow")
            .With("Right", "<Keyboard>/rightArrow");
    }

    private void OnEnable()
    {
        toggleAction.performed += OnToggle;
        toggleAction.Enable();
        moveAction.Enable();
        lookAction.Enable();
    }

    private void OnDisable()
    {
        toggleAction.performed -= OnToggle;
        toggleAction.Disable();
        moveAction.Disable();
        lookAction.Disable();
    }

    // THE HOOK: your own player code calls this.
    public void SetAvailable(bool available)
    {
        isAvailable = available;
        if (!isAvailable && IsActive)
        {
            ExitPhotoMode();   // forced out, e.g. a cutscene starts
        }
    }

    private void OnToggle(InputAction.CallbackContext context)
    {
        if (!isAvailable) return;            // guard clause

        if (IsActive) ExitPhotoMode();
        else EnterPhotoMode();
    }

    private void EnterPhotoMode()
    {
        IsActive = true;

        savedPosition = cameraTransform.position;
        savedRotation = cameraTransform.rotation;

        foreach (Behaviour script in disableWhileActive)
        {
            script.enabled = false;
        }
        if (hud != null) hud.SetActive(false);

        offset = Vector3.ClampMagnitude(cameraTransform.position - pivot.position, maxDistance);
        yaw = cameraTransform.eulerAngles.y;
        pitch = NormaliseAngle(cameraTransform.eulerAngles.x);

        savedTimeScale = Time.timeScale;
        Time.timeScale = 0f;                 // freeze the world
    }

    private void ExitPhotoMode()
    {
        IsActive = false;
        Time.timeScale = savedTimeScale;

        cameraTransform.SetPositionAndRotation(savedPosition, savedRotation);
        if (hud != null) hud.SetActive(true);

        foreach (Behaviour script in disableWhileActive)
        {
            script.enabled = true;
        }
    }

    private void LateUpdate()
    {
        if (!IsActive) return;               // guard clause

        float dt = Time.unscaledDeltaTime;   // keeps ticking while time is frozen

        Vector2 look = lookAction.ReadValue<Vector2>();
        yaw += look.x * lookSpeed * dt;
        pitch -= look.y * lookSpeed * dt;
        pitch = Mathf.Clamp(pitch, minPitch, maxPitch);
        Quaternion rotation = Quaternion.Euler(pitch, yaw, 0f);

        Vector2 move = moveAction.ReadValue<Vector2>();
        Vector3 step = rotation * new Vector3(move.x, 0f, move.y) * moveSpeed * dt;
        offset = Vector3.ClampMagnitude(offset + step, maxDistance);

        cameraTransform.SetPositionAndRotation(pivot.position + offset, rotation);
    }

    private static float NormaliseAngle(float angle)
    {
        return angle > 180f ? angle - 360f : angle;
    }
}

Now add the hook to your own code. Pick the version that matches how your controller is built.

If your game has methods (or places in Update) where the player gets in and out of a vehicle, call the hook there:

// In your own player or vehicle script
[SerializeField] private PhotoModeController photoMode;

private void Start()
{
    photoMode.SetAvailable(true);    // the player starts on foot
}

private void GetInCar()
{
    photoMode.SetAvailable(false);
    // ...your existing code
}

private void GetOutOfCar()
{
    photoMode.SetAvailable(true);
    // ...your existing code
}

If your player uses a state machine with Enter and Exit methods, the on-foot state is the natural place for the hook. It runs once when the player starts walking and once when they stop:

// In PlayerStateManager, add:  public PhotoModeController PhotoMode;
public class OnFootState : PlayerState
{
    public OnFootState(PlayerStateManager manager) : base(manager) { }

    public override void Enter()
    {
        stateManager.PhotoMode.SetAvailable(true);
        // ...your existing setup
    }

    public override void Update()
    {
        // ...your existing movement code
    }

    public override void Exit()
    {
        stateManager.PhotoMode.SetAvailable(false);
        // ...your existing clean-up
    }
}

This is the State Pattern: every state handles its own setup and clean-up, so no other state needs to know about photo mode.

Don't forget the start

If your player starts the game on foot, call SetAvailable(true) in Start too. Otherwise photo mode waits for a transition that never comes.

Extension

Solid walls

  • The camera can still pass through a cliff that is closer than 4 m. Use Physics.SphereCast from the pivot towards the new position, and stop the camera at the hit point.
  • Write the pseudocode first, then the C#, then add a test T6 for it.
  • Remember: physics queries still work while timeScale is 0.

Checkpoint

Answer all six. The first two are Foundation, the middle two are Core and the last two are Extension.

1. The player gets into a car. Which line should the car code call so photo mode can't be opened while driving?
2. Why does EnterPhotoMode switch off every script in disableWhileActive?
3. The camera's offset is 3.8 m long. This frame adds 0.5 m in the same direction, then the offset is clamped to maxDistance = 4. How far from the pivot is the camera?
4. In photo mode Time.timeScale is 0. Why does LateUpdate use Time.unscaledDeltaTime?
5. Why does photo mode rely on other code calling SetAvailable, instead of checking every frame whether the player is driving?
6. A cutscene starts while photo mode is open and calls SetAvailable(false). What does the script do?
