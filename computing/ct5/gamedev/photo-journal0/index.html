Hiking Photo Journal

Add a photo mode to your own game. Players will frame a shot while hiking, keep it in a journal, unlock achievements and play it all on Steam Deck. The goal is the polish you'd expect from a $20 game on Steam.

Teaching advice

Prerequisites: every student needs their own Unity 6 game with a working on-foot controller. The unit adds one feature to it rather than starting a new project. Students without a game can use any third-person starter controller.

Steam: the Steam client isn't needed in class. Students build against a mock platform service that behaves like Steam, then read and trace the real Steamworks.NET code. See Steam and Steam Deck below.

Pedagogy: each lesson analyses an existing system first, introduces NSW pseudocode before C#, and offers Foundation, Core and Extension tasks.

Unit overview

This unit follows the full design and production process for one feature. You'll start by studying photo modes in published games and writing requirements. Then you'll design the data and the interface, build the feature step by step, connect it to Steam, prepare it for Steam Deck, and finish by testing and evaluating your work.

By the end, your game will let players:

  • open photo mode while hiking, then aim and capture a photo without the HUD in the shot
  • save each photo with a caption, location and date, and find it again after restarting the game
  • browse their photos in a journal that works with a controller alone
  • unlock achievements and send photos to their Steam screenshot library.

The feature

The whole feature as an input–process–output chain. Each lesson builds one part of it.

Input

Player presses the photo button while hiking, aims with the stick, then presses capture.

→
Process

Check photo mode is allowed, hide the HUD, capture the screen, save the image and update the journal.

→
Output

Shutter feedback, a new journal entry, an achievement unlock and a Steam screenshot.

Steam and Steam Deck

Real games talk to platforms like Steam to unlock achievements and save screenshots. School computers usually can't run Steam, so the code for this feature never talks to Steam directly. It talks to an interface instead.

IPlatformService
The interface: a list of what any platform must be able to do, such as unlock an achievement, add a screenshot or show a keyboard.
MockPlatformService
Used in class. It shows an achievement pop-up on screen and logs screenshots, so every lesson can be tested without Steam.
SteamPlatformService
The real version, using Steamworks.NET and Valve's free test app, Spacewar (App ID 480). You'll read and trace it in Lesson 9.
Why Spacewar? Valve provides Spacewar so any developer can test Steam features without owning a game listing. It comes with a fixed set of achievements, so our achievements (like "first photo") are mapped to Spacewar's in one lookup table. A real release would change that one table.

Steam Deck shapes our design from Lesson 1: every screen must work with a controller alone, text must be readable at 1280 × 800, and typing a caption must open an on-screen keyboard. Lesson 10 checks your game against these requirements.
