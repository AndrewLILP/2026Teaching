Lesson 4 of 12 · 50 minutes

Capturing the shot

Photo mode opens and the camera moves. Now the player presses the shutter. Today you'll capture exactly what's on screen, without any prompts in the way, save it as a PNG file, and make the moment feel satisfying with a sound and a flash. This is where your game starts to feel like a product.

Producing & implementing
Last lesson: you added PhotoModeController, connected it to your game with the SetAvailable hook, and saw why the camera needs unscaled time while the world is frozen. That idea comes back today in the flash effect.

Teaching advice

Timing: recap and vocabulary 5 min · sequencing 5 min · frame timeline 4 min · pseudocode and code walkthrough 12 min · unique names and bug detective 6 min · setup and testing 13 min · checkpoint 5 min.

Prerequisite: students need Lesson 3 working (tests T1 and T4 passing). Pair anyone who isn't there yet with a student who is, and let them catch up using Lesson 3's full script.

Editor tip: keep the Game view visible while testing in the Editor. The capture copies whatever the Game view has just drawn. The Console prints the photo folder location the first time the script runs.

Learning intentions

By the end of this lesson I can:

  • explain why a screen capture must wait until the end of the frame
  • use a coroutine to spread a task across several frames
  • use a WHILE loop to make sure no saved photo is ever overwritten
  • add feedback that makes an action feel responsive to the player.
Success criteria: pressing capture in my game saves a PNG with no prompts or HUD in it, plays a shutter sound and flashes the screen, and pressing it rapidly never overwrites an earlier photo.

Key vocabulary

Analysing

Sequence a shutter press

In a well-made photo mode, a lot happens in the split second after the player presses capture. Order matters: get it wrong and the photo is ruined.

DART · sequencing · pairs · 5 min

These steps are scrambled. Write the letters in the order they must happen, and be ready to justify any step that must come before another.

  1. Play the shutter sound and flash the screen white
  2. Copy the finished frame into a texture
  3. Check the player is in photo mode and not already taking a photo
  4. Tell the rest of the game a photo was saved
  5. Hide the button prompts
  6. Wait until the frame has finished drawing
  7. Choose a file name no other photo is using, then save the PNG

C → E → F → B → G → A → D.

C first: this is the guard pattern again. Nothing happens unless it's safe. E before F: prompts must be hidden before the frame is drawn, or they'll appear in the photo. F before B: a half-drawn frame would give a broken image. A after B: flash before capturing and every photo is white. D last: other scripts should only hear about the photo once the file really exists.

Inside one frame

Every frame, Unity runs your scripts, then draws the scene, then shows the result. A screen capture copies what has been drawn, so it has to happen after drawing finishes.

1 · Input

Button presses are read. Our OnCapture runs here.

→
2 · Update

Scripts run Update and LateUpdate. The camera moves.

→
3 · Render

The scene, then the UI, are drawn into the frame.

→
4 · End of frame

Drawing is complete. WaitForEndOfFrame resumes here, so we capture now.

A normal method has to finish all its work inside one of these steps. A coroutine can pause at step 1, wait for step 4, then keep going, and later pause again for each frame of the flash. That's why the capture is written as a coroutine.

Producing

Into C#

The new script, PhotoCapture, sits next to PhotoModeController. It only reads photoMode.IsActive, so Lesson 3's script doesn't change.

1Two guard clauses, then start the coroutine
private void OnCapture(InputAction.CallbackContext context)
{
    if (!photoMode.IsActive) return;     // guard clause: not in photo mode
    if (isCapturing) return;             // guard clause: already taking a photo
    StartCoroutine(CaptureRoutine());
}
These match pseudocode lines 2–7. StartCoroutine begins the capture but doesn't wait for it to finish. Without the isCapturing guard, pressing twice quickly would start two captures at the same time.
2The capture coroutine
private IEnumerator CaptureRoutine()
{
    isCapturing = true;
    if (photoModeOverlay != null) photoModeOverlay.SetActive(false);

    yield return new WaitForEndOfFrame();       // wait until the frame is fully drawn

    Texture2D shot = ScreenCapture.CaptureScreenshotAsTexture();
    byte[] png = shot.EncodeToPNG();
    Destroy(shot);                              // free the texture's memory

    string fileName = MakeUniqueFileName();
    File.WriteAllBytes(Path.Combine(photoFolder, fileName), png);

    if (shutterSound != null) shutterSound.Play();
    yield return Flash();

    PhotoSaved?.Invoke(fileName);
    isCapturing = false;
}
IEnumerator marks this as a coroutine. Each yield return is a pause: the first waits for the end of the frame, the second waits for the whole flash to finish. Destroy(shot) matters. A 1080p texture uses about 8 MB of memory, and without it every photo would leak another 8 MB.
3The flash: a loop across frames
private IEnumerator Flash()
{
    if (flashImage == null) yield break;        // guard clause

    float elapsed = 0f;
    while (elapsed < flashDuration)
    {
        elapsed += Time.unscaledDeltaTime;      // real time: the world is frozen
        float alpha = 1f - (elapsed / flashDuration);
        flashImage.color = new Color(1f, 1f, 1f, alpha);
        yield return null;                      // wait one frame
    }
    flashImage.color = new Color(1f, 1f, 1f, 0f);
}
Each time round the WHILE loop, the image gets a little more see-through, then yield return null waits one frame. Over 0.25 seconds, alpha goes from 1 (solid white) to 0 (invisible). It uses Time.unscaledDeltaTime for the same reason as the camera in Lesson 3: the world is frozen.
4Keeping the prompts in step
// Keeps the photo mode prompts in step with photo mode.
private void Update()
{
    if (photoModeOverlay == null || isCapturing) return;   // guard clause
    photoModeOverlay.SetActive(photoMode.IsActive);
}
Every frame, the prompts copy whether photo mode is on, except while a capture is in progress, when the coroutine is in charge of hiding them. One more guard clause.

Unique file names

In Lesson 2, file names were built from the date and time, down to the second. But a player can easily take two photos in the same second, and saving the second one with the same name would silently replace the first. A WHILE loop fixes this.

NSW pseudocode · MakeUniqueFileName

1   BEGIN MakeUniqueFileName
2       SET baseName TO "photo_" + FileSafe(CurrentDateTime())
3       SET fileName TO baseName + ".png"
4       SET copy TO 2
5       WHILE file fileName exists
6           SET fileName TO baseName + "_" + copy + ".png"
7           SET copy TO copy + 1
8       ENDWHILE
9       RETURN fileName
10  END MakeUniqueFileName
5The same algorithm in C#
private string MakeUniqueFileName()
{
    string baseName = "photo_" + DateTime.Now.ToString("yyyyMMdd_HHmmss");
    string fileName = baseName + ".png";
    int copy = 2;
    while (File.Exists(Path.Combine(photoFolder, fileName)))   // same second? add a number
    {
        fileName = baseName + "_" + copy + ".png";
        copy++;
    }
    return fileName;
}
"yyyyMMdd_HHmmss" is the FileSafe format from Lesson 2: no colons, year first so names sort in date order. Path.Combine joins folder and file names with the correct separator for each operating system, which matters on Steam Deck's Linux.

Bug detective

Every photo is white

A classmate's capture saves PNG files, plays the sound and flashes, but every photo is solid white or very washed out. Here's their coroutine:

private IEnumerator CaptureRoutine()
{
    isCapturing = true;
    shutterSound.Play();
    StartCoroutine(Flash());
    yield return new WaitForEndOfFrame();
    Texture2D shot = ScreenCapture.CaptureScreenshotAsTexture();
The flash starts before the capture, so the first frame of the flash, a full-screen white image, is drawn into the very frame being captured. Feedback must come after the capture: move the sound and flash below the CaptureScreenshotAsTexture line. This is step A coming before step B from the sequencing activity.
Producing

Set it up

Setup · follow along · 8 min

  1. Create a script called PhotoCapture, paste in the full script below, and add it to your PhotoMode object. Space or gamepad A is set as the capture button.
  2. Drag the PhotoMode object's own PhotoModeController into the Photo Mode slot.
  3. Prompts: create a UI canvas called PhotoModeOverlay with a text line such as "Ⓐ Capture · Ⓨ Exit". Drag it into Photo Mode Overlay.
  4. Flash: create a separate canvas called FlashCanvas with one full-screen white Image. Set its alpha to 0 and untick Raycast Target. Drag the Image into Flash Image.
  5. Sound: add an AudioSource with a short shutter click (free sound sites have many) and untick Play On Awake. Drag it into Shutter Sound.

Why a separate flash canvas?

The overlay is hidden during the capture. If the flash lived on the same canvas, it would be hidden too, and the player would see nothing.

// Recommended filename: PhotoCapture.cs
using System;
using System.Collections;
using System.IO;
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.UI;

public class PhotoCapture : MonoBehaviour
{
    [Header("Input (defaults are set when you add the component)")]
    [SerializeField] private InputAction captureAction;

    [Header("Scene references")]
    [SerializeField] private PhotoModeController photoMode;
    [SerializeField] private GameObject photoModeOverlay;   // button prompts shown in photo mode
    [SerializeField] private AudioSource shutterSound;
    [SerializeField] private Image flashImage;              // full-screen white Image on its own canvas

    [Header("Feedback")]
    [SerializeField] private float flashDuration = 0.25f;   // seconds

    // Lesson 5's journal listens for this.
    public event Action<string> PhotoSaved;

    private bool isCapturing;
    private string photoFolder;

    // Runs when the component is first added: fills in default controls.
    private void Reset()
    {
        captureAction = new InputAction("Capture", InputActionType.Button);
        captureAction.AddBinding("<Keyboard>/space");
        captureAction.AddBinding("<Gamepad>/buttonSouth");
    }

    private void Awake()
    {
        photoFolder = Path.Combine(Application.persistentDataPath, "Journal");
        Directory.CreateDirectory(photoFolder);     // does nothing if it already exists
        Debug.Log("Photos are saved to: " + photoFolder);
    }

    private void OnEnable()
    {
        captureAction.performed += OnCapture;
        captureAction.Enable();
    }

    private void OnDisable()
    {
        captureAction.performed -= OnCapture;
        captureAction.Disable();
    }

    // Keeps the photo mode prompts in step with photo mode.
    private void Update()
    {
        if (photoModeOverlay == null || isCapturing) return;   // guard clause
        photoModeOverlay.SetActive(photoMode.IsActive);
    }

    private void OnCapture(InputAction.CallbackContext context)
    {
        if (!photoMode.IsActive) return;     // guard clause: not in photo mode
        if (isCapturing) return;             // guard clause: already taking a photo
        StartCoroutine(CaptureRoutine());
    }

    private IEnumerator CaptureRoutine()
    {
        isCapturing = true;
        if (photoModeOverlay != null) photoModeOverlay.SetActive(false);

        yield return new WaitForEndOfFrame();       // wait until the frame is fully drawn

        Texture2D shot = ScreenCapture.CaptureScreenshotAsTexture();
        byte[] png = shot.EncodeToPNG();
        Destroy(shot);                              // free the texture's memory

        string fileName = MakeUniqueFileName();
        File.WriteAllBytes(Path.Combine(photoFolder, fileName), png);

        if (shutterSound != null) shutterSound.Play();
        yield return Flash();

        PhotoSaved?.Invoke(fileName);
        isCapturing = false;
    }

    private string MakeUniqueFileName()
    {
        string baseName = "photo_" + DateTime.Now.ToString("yyyyMMdd_HHmmss");
        string fileName = baseName + ".png";
        int copy = 2;
        while (File.Exists(Path.Combine(photoFolder, fileName)))   // same second? add a number
        {
            fileName = baseName + "_" + copy + ".png";
            copy++;
        }
        return fileName;
    }

    private IEnumerator Flash()
    {
        if (flashImage == null) yield break;        // guard clause

        float elapsed = 0f;
        while (elapsed < flashDuration)
        {
            elapsed += Time.unscaledDeltaTime;      // real time: the world is frozen
            float alpha = 1f - (elapsed / flashDuration);
            flashImage.color = new Color(1f, 1f, 1f, alpha);
            yield return null;                      // wait one frame
        }
        flashImage.color = new Color(1f, 1f, 1f, 0f);
    }
}
Where are my photos? The Console shows the path when the game starts. On Windows it's under AppData\LocalLow\, on macOS under ~/Library/Application Support/, and on Linux and Steam Deck under ~/.config/unity3d/, each followed by your company and product names and then Journal.

Your task

Foundation

First photo

  • Complete the setup and take three photos in different places.
  • Find them in the Journal folder and run tests T6, T7 and T9.
  • Number the lines of CaptureRoutine to match the pseudocode line numbers.
Core

Make it feel right

  • Run all five tests and fix any that fail.
  • Desk-check MakeUniqueFileName for a 4th photo in the same second.
  • Tune the flash duration and colour, and choose a sound that fits your game's mood. Record your choices and reasons. That's design thinking.
Extension

No stutter (R4)

  • Open the Profiler (Window → Analysis), capture a photo, and find the frame spike. Record how many milliseconds it took.
  • Writing the file is slow. Move File.WriteAllBytes onto a background thread with System.Threading.Tasks.Task.Run, and wait for it to finish before raising PhotoSaved.
  • Measure again and compare the two results.

Checkpoint

Answer all six. The first two are Foundation, the middle two are Core and the last two are Extension.

1. Why does the capture coroutine use yield return new WaitForEndOfFrame() before capturing the screen?
2. Where does PhotoCapture save each photo?
3. The Journal folder already holds photo_20261002_143012.png and photo_20261002_143012_2.png. Another photo is taken in that same second. What does MakeUniqueFileName return?
4. The player presses capture twice very quickly. What stops two capture coroutines running at the same time?
5. In photo mode, Time.timeScale is 0. What would happen if Flash() used Time.deltaTime instead of Time.unscaledDeltaTime?
6. Why does PhotoCapture raise a PhotoSaved event instead of adding the photo to the journal itself?
