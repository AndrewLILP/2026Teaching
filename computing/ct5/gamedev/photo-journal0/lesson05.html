Lesson 5 of 12 · 50 minutes

Saving and loading

Your game can take photos, but quit and restart and it has forgotten them all. Today you'll build the journal: it records every photo with its location and time, saves to journal.json in a way that survives crashes, and checks everything it loads. Nothing frustrates players more than losing their progress.

Producing & implementing
Last lesson: PhotoCapture saved each photo as a PNG, then announced it with the PhotoSaved event. Today's Journal script is the listener, and it builds the JournalEntry records you designed in Lesson 2.

Teaching advice

Timing: recap and vocabulary 5 min · risk analysis 6 min · memory and disk 4 min · pseudocode and code walkthrough 12 min · crash desk check and bug detective 6 min · setup and testing 12 min · checkpoint 5 min.

Common errors: JsonUtility only saves classes marked [Serializable], only saves public fields, and can't save a bare List. That's why the list lives inside a JournalData wrapper. If journal.json comes out as {}, check these three first.

Testing tip: set Max Photos to 3 in the Inspector to test the full-journal guard quickly, then set it back to 50.

Learning intentions

By the end of this lesson I can:

  • serialise data to JSON and deserialise it back into objects
  • explain how writing to a temporary file protects a save from crashes
  • validate loaded data and handle a damaged file without crashing
  • explain why a loop that removes items should count backwards.
Success criteria: photos in my journal survive a restart, each with a location and time. A deleted PNG or a damaged save file doesn't crash the game, and capturing stops with a message when the journal is full.

Key vocabulary

Analysing

What could go wrong?

Saving seems simple: write the data to a file. But real players do unexpected things, and real computers lose power. Professional developers list the risks before writing the save code.

Analysis activity · pairs · 6 min

Predict the problem

For each situation, predict what would happen with a simple "just write the file" save, then suggest what the game should do.

#SituationSimple save would…Should…
1A brand-new player starts the game. There is no save file yet.
2The Steam Deck battery dies halfway through writing journal.json.
3A player deletes some PNG files from the Journal folder to free up space.
4A curious player opens journal.json in Notepad and accidentally deletes a bracket.
5A player takes their 51st photo.
  1. No file: a guard clause in Load returns early and the journal starts empty, with no error.
  2. Power loss: the new save is written to a temporary file first, so the old save is never half-overwritten. If needed, Load recovers from the temporary file.
  3. Missing photos: Load validates every entry and removes any whose PNG no longer exists, so the journal never shows a blank photo.
  4. Damaged file: try / catch handles the error, logs a warning and starts an empty journal instead of crashing.
  5. 51st photo: the new guard clause in PhotoCapture shows "Journal full" and nothing is saved.

Memory and disk

While the game runs, the journal lives in memory as C# objects. Memory is fast but is wiped when the game closes. To persist, the data is converted to text and written to disk.

Planning

Pseudocode first

NSW pseudocode · Save (crash-safe)

1   BEGIN Save
2       SET json TO Serialise(journalData)
3       WRITE json TO "journal.json.tmp"
4       IF "journal.json" exists THEN
5           DELETE "journal.json"
6       ENDIF
7       RENAME "journal.json.tmp" TO "journal.json"
8   END Save

NSW pseudocode · Load (with recovery and validation)

1   BEGIN Load
2       SET path TO "journal.json"
3       IF path does not exist THEN
4           IF "journal.json.tmp" does not exist THEN
5               RETURN
6           ENDIF
7           SET path TO "journal.json.tmp"
8       ENDIF
9       TRY
10          SET journalData TO Deserialise(READ path)
11      CATCH damaged file
12          DISPLAY warning
13          SET journalData TO empty journal
14          RETURN
15      ENDTRY
16      SET i TO number of entries − 1
17      WHILE i >= 0
18          IF photo for entry i does not exist THEN
19              REMOVE entry i
20          ENDIF
21          SET i TO i − 1
22      ENDWHILE
23      Save()
24  END Load

Lines 16–22 count backwards from the last entry. The bug detective below shows why.

[Serializable]
public class JournalData
{
    public List<JournalEntry> entries = new List<JournalEntry>();
}
Each field is one row of your Lesson 2 data dictionary. [Serializable] lets JsonUtility convert these classes to JSON. The fields are public because JsonUtility only saves public fields (or ones marked [SerializeField]).
2Listening for new photos
private void OnPhotoSaved(string fileName)
{
    JournalEntry entry = new JournalEntry
    {
        fileName = fileName,
        caption = "",
        locationName = currentLocation,
        timestamp = DateTime.Now.ToString("yyyy-MM-ddTHH:mm:ss", CultureInfo.InvariantCulture)
    };
    data.entries.Add(entry);
    Save();
    JournalChanged?.Invoke();
}
This runs whenever PhotoCapture raises PhotoSaved. It builds a new record, adds it, saves, then raises its own event, JournalChanged, which Lesson 6's journal screen will listen for.
3Crash-safe saving
private void Save()
{
    string json = JsonUtility.ToJson(data, true);
    File.WriteAllText(tempPath, json);                  // 1. write the new version beside the old one
    if (File.Exists(savePath)) File.Delete(savePath);   // 2. remove the old version
    File.Move(tempPath, savePath);                      // 3. rename the new version into place
}
The true in ToJson means "pretty print", which adds line breaks so you can read the file. The three numbered comments match pseudocode lines 3, 4–6 and 7.
4Loading with recovery and a safety net
private void Load()
{
    string path = savePath;
    if (!File.Exists(path))
    {
        if (!File.Exists(tempPath)) return;     // guard clause: first time playing
        path = tempPath;                        // recover from an interrupted save
    }

    try
    {
        data = JsonUtility.FromJson<JournalData>(File.ReadAllText(path)) ?? new JournalData();
    }
    catch (ArgumentException)
    {
        Debug.LogWarning("journal.json was damaged, so the journal is starting empty.");
        data = new JournalData();
        return;
    }

    RemoveMissingPhotos();
    Save();                                     // tidy up: one clean, valid save file
}
If the code inside try throws an exception, the program jumps straight to catch instead of crashing. ?? new JournalData() means "if the result is null, use an empty journal instead". The final Save() leaves exactly one clean, validated journal.json.
5Validation: removing missing photos
private void RemoveMissingPhotos()
{
    for (int i = data.entries.Count - 1; i >= 0; i--)   // count backwards when removing
    {
        string photoPath = Path.Combine(photoFolder, data.entries[i].fileName);
        if (!File.Exists(photoPath))
        {
            data.entries.RemoveAt(i);
        }
    }
}
A for loop is a counted loop. This one starts at the last index and counts down to 0, matching pseudocode lines 16–22.

Why InvariantCulture?

Date formats depend on a computer's language settings. On a computer set to Thai, this same code would write the year as 2569 (Buddhist calendar). CultureInfo.InvariantCulture makes every computer write 2026-10-02T14:30:12. We checked both by running them.

Desk check: crashes

The journal already holds one photo ("old"). The player takes a second ("new"), and the game crashes at different points during Save. What's on disk, and what does Load find next time?

Crash afterFiles on diskLoad usesJournal after restart
Step 1 (write .tmp)journal.json, journal.json.tmpjournal.jsonold, which is safe (newest photo lost)
Step 2 (delete old)journal.json.tmpjournal.json.tmpold + new, recovered
No crashjournal.jsonjournal.jsonold + new

In every case the player keeps a working journal. Compare that with writing straight into journal.json: a crash halfway through would leave a half-written file and lose everything. These three results came from running the save code and stopping it at each step.

Bug detective

One missing photo survives

A classmate counts forwards instead. Their journal holds entries A, B and C. The player deleted the PNGs for A and B, but after loading, the journal still shows B.

for (int i = 0; i < data.entries.Count; i++)
{
    string photoPath = Path.Combine(photoFolder, data.entries[i].fileName);
    if (!File.Exists(photoPath))
    {
        data.entries.RemoveAt(i);
    }
}
When i = 0, A is removed and everything shifts left: B moves to index 0 and C to index 1. Then i becomes 1, which checks C. B was never checked. Counting backwards avoids this, because removing an item only shifts the items after it, and those have already been checked. We ran both loops: forwards leaves [B, C], backwards leaves [C].

    {

        return;
    }

private IEnumerator ShowFullMessage()
{
    if (journalFullMessage == null) yield break;   // guard clause
    journalFullMessage.SetActive(true);
    yield return new WaitForSecondsRealtime(2f);   // real seconds: the world is frozen
    journalFullMessage.SetActive(false);
}
WaitForSecondsRealtime is the real-time version of WaitForSeconds. You know why by now: the world is frozen in photo mode.

// Recommended filename: Journal.cs
using System;
using System.Collections.Generic;
using System.Globalization;
using System.IO;
using UnityEngine;

[Serializable]
public class JournalEntry
{
    public string fileName;
    public string caption;
    public string locationName;
    public string timestamp;
}

// JsonUtility can't save a List on its own, so it goes inside a wrapper class.
[Serializable]
public class JournalData
{
    public List<JournalEntry> entries = new List<JournalEntry>();
}

public class Journal : MonoBehaviour
{
    [SerializeField] private PhotoCapture photoCapture;
    [SerializeField] private int maxPhotos = 50;

    // Lesson 6's journal screen listens for this.
    public event Action JournalChanged;

    public IReadOnlyList<JournalEntry> Entries => data.entries;
    public bool IsFull => data.entries.Count >= maxPhotos;
    public string PhotoFolder => photoFolder;

    private JournalData data = new JournalData();
    private string currentLocation = "Unknown trail";
    private string photoFolder;
    private string savePath;
    private string tempPath;

    private void Awake()
    {
        photoFolder = Path.Combine(Application.persistentDataPath, "Journal");
        Directory.CreateDirectory(photoFolder);
        savePath = Path.Combine(photoFolder, "journal.json");
        tempPath = savePath + ".tmp";
        Load();
    }

    private void OnEnable()
    {
        photoCapture.PhotoSaved += OnPhotoSaved;
    }

    private void OnDisable()
    {
        photoCapture.PhotoSaved -= OnPhotoSaved;
    }

    // A second hook: location zones in your world call this.
    public void SetLocation(string locationName)
    {
        currentLocation = locationName;
    }

    private void OnPhotoSaved(string fileName)
    {
        JournalEntry entry = new JournalEntry
        {
            fileName = fileName,
            caption = "",
            locationName = currentLocation,
            timestamp = DateTime.Now.ToString("yyyy-MM-ddTHH:mm:ss", CultureInfo.InvariantCulture)
        };
        data.entries.Add(entry);
        Save();
        JournalChanged?.Invoke();
    }

    public void DeleteEntry(JournalEntry entry)
    {
        if (!data.entries.Contains(entry)) return;      // guard clause

        string photoPath = Path.Combine(photoFolder, entry.fileName);
        if (File.Exists(photoPath)) File.Delete(photoPath);
        data.entries.Remove(entry);
        Save();
        JournalChanged?.Invoke();
    }

    private void Save()
    {
        string json = JsonUtility.ToJson(data, true);
        File.WriteAllText(tempPath, json);                  // 1. write the new version beside the old one
        if (File.Exists(savePath)) File.Delete(savePath);   // 2. remove the old version
        File.Move(tempPath, savePath);                      // 3. rename the new version into place
    }

    private void Load()
    {
        string path = savePath;
        if (!File.Exists(path))
        {
            if (!File.Exists(tempPath)) return;     // guard clause: first time playing
            path = tempPath;                        // recover from an interrupted save
        }

        try
        {
            data = JsonUtility.FromJson<JournalData>(File.ReadAllText(path)) ?? new JournalData();
        }
        catch (ArgumentException)
        {
            Debug.LogWarning("journal.json was damaged, so the journal is starting empty.");
            data = new JournalData();
            return;
        }

        RemoveMissingPhotos();
        Save();                                     // tidy up: one clean, valid save file
    }

    private void RemoveMissingPhotos()
    {
        for (int i = data.entries.Count - 1; i >= 0; i--)   // count backwards when removing
        {
            string photoPath = Path.Combine(photoFolder, data.entries[i].fileName);
            if (!File.Exists(photoPath))
            {
                data.entries.RemoveAt(i);
            }
        }
    }
}

using UnityEngine;

[RequireComponent(typeof(Collider))]
public class LocationZone : MonoBehaviour
{
    [SerializeField] private string locationName = "Lookout Point";
    [SerializeField] private Journal journal;
    [SerializeField] private string playerTag = "Player";

    private void OnTriggerEnter(Collider other)
    {
        if (!other.CompareTag(playerTag)) return;   // guard clause: only the player counts
        journal.SetLocation(locationName);
    }
}
// Recommended filename: PhotoCapture.cs
using System;
using System.Collections;
using System.IO;
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.UI;

public class PhotoCapture : MonoBehaviour
{
    [Header("Input (defaults are set when you add the component)")]
    [SerializeField] private InputAction captureAction;

    [Header("Scene references")]
    [SerializeField] private PhotoModeController photoMode;
    [SerializeField] private Journal journal;
    [SerializeField] private GameObject journalFullMessage; // hidden "Journal full" text
    [SerializeField] private GameObject photoModeOverlay;   // button prompts shown in photo mode
    [SerializeField] private AudioSource shutterSound;
    [SerializeField] private Image flashImage;              // full-screen white Image on its own canvas

    [Header("Feedback")]
    [SerializeField] private float flashDuration = 0.25f;   // seconds

    // Lesson 5's journal listens for this.
    public event Action<string> PhotoSaved;

    private bool isCapturing;
    private string photoFolder;

    // Runs when the component is first added: fills in default controls.
    private void Reset()
    {
        captureAction = new InputAction("Capture", InputActionType.Button);
        captureAction.AddBinding("<Keyboard>/space");
        captureAction.AddBinding("<Gamepad>/buttonSouth");
    }

    private void Awake()
    {
        photoFolder = Path.Combine(Application.persistentDataPath, "Journal");
        Directory.CreateDirectory(photoFolder);     // does nothing if it already exists
        Debug.Log("Photos are saved to: " + photoFolder);
    }

    private void OnEnable()
    {
        captureAction.performed += OnCapture;
        captureAction.Enable();
    }

    private void OnDisable()
    {
        captureAction.performed -= OnCapture;
        captureAction.Disable();
    }

    // Keeps the photo mode prompts in step with photo mode.
    private void Update()
    {
        if (photoModeOverlay == null || isCapturing) return;   // guard clause
        photoModeOverlay.SetActive(photoMode.IsActive);
    }

    private void OnCapture(InputAction.CallbackContext context)
    {
        if (!photoMode.IsActive) return;     // guard clause: not in photo mode
        if (isCapturing) return;             // guard clause: already taking a photo
        if (journal != null && journal.IsFull)   // guard clause: no room left
        {
            StartCoroutine(ShowFullMessage());
            return;
        }
        StartCoroutine(CaptureRoutine());
    }

    private IEnumerator ShowFullMessage()
    {
        if (journalFullMessage == null) yield break;   // guard clause
        journalFullMessage.SetActive(true);
        yield return new WaitForSecondsRealtime(2f);   // real seconds: the world is frozen
        journalFullMessage.SetActive(false);
    }

    private IEnumerator CaptureRoutine()
    {
        isCapturing = true;
        if (photoModeOverlay != null) photoModeOverlay.SetActive(false);

        yield return new WaitForEndOfFrame();       // wait until the frame is fully drawn

        Texture2D shot = ScreenCapture.CaptureScreenshotAsTexture();
        byte[] png = shot.EncodeToPNG();
        Destroy(shot);                              // free the texture's memory

        string fileName = MakeUniqueFileName();
        File.WriteAllBytes(Path.Combine(photoFolder, fileName), png);

        if (shutterSound != null) shutterSound.Play();
        yield return Flash();

        PhotoSaved?.Invoke(fileName);
        isCapturing = false;
    }

    private string MakeUniqueFileName()
    {
        string baseName = "photo_" + DateTime.Now.ToString("yyyyMMdd_HHmmss");
        string fileName = baseName + ".png";
        int copy = 2;
        while (File.Exists(Path.Combine(photoFolder, fileName)))   // same second? add a number
        {
            fileName = baseName + "_" + copy + ".png";
            copy++;
        }
        return fileName;
    }

    private IEnumerator Flash()
    {
        if (flashImage == null) yield break;        // guard clause

        float elapsed = 0f;
        while (elapsed < flashDuration)
        {
            elapsed += Time.unscaledDeltaTime;      // real time: the world is frozen
            float alpha = 1f - (elapsed / flashDuration);
            flashImage.color = new Color(1f, 1f, 1f, alpha);
            yield return null;                      // wait one frame
        }
        flashImage.color = new Color(1f, 1f, 1f, 0f);
    }
}

Checkpoint

Answer all six. The first two are Foundation, the middle two are Core and the last two are Extension.

1. Why is the JournalEntry class marked [Serializable]?
2. When does the journal read journal.json from disk?
3. The game crashes after step 2 of Save (the old journal.json was deleted) but before step 3 (the rename). What happens on the next launch?
