Key vocabulary

Researching

How Steam Deck games are rated

Valve tests games on Steam Deck and shows a rating on each game's store page. The ratings are Verified (works great out of the box), Playable (works, but the player may need to adjust something, such as using the touchscreen or a mouse mode), Unsupported and Unknown. The checks fall into four categories. These are summarised in our own words:

CategoryThe question it asksWhere our unit addressed it
InputCan every part of the game be used with the Deck's built-in controls? Do on-screen prompts show Deck buttons? Does typing bring up an on-screen keyboard?Lessons 3, 6, 7 and 9: R5, prompts, keyboard
DisplayDoes the game support the Deck's 1280 × 800 screen, and is all text easy to read at that size?Lessons 2 and 6: storyboard, 24 px rule
SeamlessnessDoes the game run smoothly without stopping to show warnings, or needing a mouse-only screen such as a launcher?Lessons 5 and 7: no crashes on bad saves, no mouse-only screens
System supportDoes the game run on the Deck's operating system, which is Linux-based (natively or through Valve's Proton compatibility layer)?Today: Linux build

Notice that most of these are non-functional requirements, the "how well" requirements from Lesson 1. A game can have every feature and still not be Verified.

Frame rate and frame time

Performance is part of "runs smoothly". Developers usually think in frame time, because that's the budget each frame must fit inside.

We do · calculation · 3 min

  1. At 30 fps, how many milliseconds does each frame have? (1 second = 1000 ms.)
  2. At 60 fps?
  3. A game averages 16 ms per frame, but every few seconds one frame takes 120 ms. What will the player notice?
  1. 1000 ÷ 30 ≈ 33.3 ms.
  2. 1000 ÷ 60 ≈ 16.7 ms.
  3. The average is about 60 fps, which looks great on paper, but each 120 ms frame is a visible freeze: a stutter. That's why our tool reports the worst frame as well as the average. The capture hitch from Lesson 4 is exactly this kind of spike.
Testing

Measuring performance

One frame's time jumps around too much to read, and an average since the game started would hide recent problems. A rolling average of the last 60 frames shows what the game is doing right now. We store the times in a circular buffer: an array of 60 slots where each new time overwrites the oldest.

NSW pseudocode · RecordFrame and the readout

1   BEGIN RecordFrame(frameTime)
2       SET samples[index] TO frameTime
3       SET index TO (index + 1) MOD length of samples
4       IF count < length of samples THEN
5           SET count TO count + 1
6       ENDIF
7   END RecordFrame

8   BEGIN ShowReadout
9       SET total TO 0
10      SET worst TO 0
11      FOR i FROM 0 TO count − 1
12          SET total TO total + samples[i]
13          IF samples[i] > worst THEN
14              SET worst TO samples[i]
15          ENDIF
16      NEXT i
17      SET average TO total ÷ count
18      DISPLAY 1 ÷ average AS fps, average, worst
19  END ShowReadout
1The circular buffer
// A circular buffer: the newest time replaces the oldest once the array is full.
private void RecordFrame(float frameTime)
{
    samples[index] = frameTime;
    index = (index + 1) % samples.Length;           // 59 + 1 wraps back to 0
    if (count < samples.Length) count++;
}
% is MOD: the remainder after dividing. Counting 57, 58, 59, then 60 % 60 = 0, so the index wraps to the start. count stops at 60, so the average only uses slots that have been filled.
2Average, worst and memory
private void ShowReadout()
{
    float total = 0f;
    float worst = 0f;
    for (int i = 0; i < count; i++)
    {
        total += samples[i];
        if (samples[i] > worst) worst = samples[i];
    }
    float average = total / count;
    float fps = 1f / average;
    float memoryMB = Profiler.GetTotalAllocatedMemoryLong() / 1000000f;

    readout.text = $"{fps:0} fps   avg {average * 1000f:0.0} ms   worst {worst * 1000f:0.0} ms   {memoryMB:0} MB";
    readout.color = fps >= targetFps ? Color.green : Color.red;
}
One loop finds both the total and the worst. Memory comes from Unity's Profiler. Opening and closing your journal ten times is a quick check that the Lesson 6 leak fix is still working: memory should go up and back down, not keep climbing. Red text means below the 30 fps target.

Desk check: a buffer of 4

To trace by hand, shrink the buffer to 4 slots. Frame times arrive: 20, 20, 40, 20, 60 ms.

Frame time insamples afterindexcount
20[20, 0, 0, 0]11
20[20, 20, 0, 0]22
40[20, 20, 40, 0]33
20[20, 20, 40, 20]4 % 4 = 04
60[60, 20, 40, 20]14 (oldest 20 overwritten)

Average = (60 + 20 + 40 + 20) ÷ 4 = 35 ms (about 28.6 fps), and worst = 60 ms. We ran the buffer code on these values to confirm every row.

Bug detective

The readout crashes after one second

A classmate's performance readout works for about a second, then the Console fills with IndexOutOfRangeException errors every frame.

private void RecordFrame(float frameTime)
{
    samples[index] = frameTime;
    index++;
    if (count < samples.Length) count++;
}
index never wraps. After 60 frames (about a second at 60 fps) it reaches 60, but the array's last slot is 59, so samples[60] is out of range. The fix is index = (index + 1) % samples.Length;. We ran the unwrapped version, and it throws exactly this exception on the first frame past the end.

Automating the text check

Checking every text by eye is slow, and it's easy to miss one hidden on a panel you rarely open. When a check is repetitive and rule-based, let code do it.

3AuditTextSizes (press F4)
// Lists every TextMesh Pro text in the scene smaller than the design rule.
private void AuditTextSizes()
{
    int problems = 0;
    TMP_Text[] texts = FindObjectsByType<TMP_Text>(FindObjectsInactive.Include, FindObjectsSortMode.None);
    foreach (TMP_Text text in texts)
    {
        float smallest = text.enableAutoSizing ? text.fontSizeMin : text.fontSize;
        if (smallest < minTextSize)
        {
            Debug.LogWarning($"Text too small ({smallest} px): {text.name}", text);
            problems++;
        }
    }
    Debug.Log($"Text audit: checked {texts.Length} texts, {problems} below {minTextSize} px.");
}
FindObjectsInactive.Include also finds texts on hidden panels, like the caption box and delete confirmation, which are the ones most likely to be missed. Passing text as the second argument to LogWarning means clicking the warning in the Console highlights that object in the Hierarchy. This assumes your Canvas Scaler's reference resolution is 1280 × 800, as set in Lesson 6, so font sizes equal pixels on Steam Deck.
// Recommended filename: DeckReadinessTools.cs
// Developer tools for Lesson 10. F3 shows performance; F4 audits text sizes.
using TMPro;
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.Profiling;

public class DeckReadinessTools : MonoBehaviour
{
    [Header("Performance readout (F3)")]
    [SerializeField] private TMP_Text readout;
    [SerializeField] private float targetFps = 30f;

    [Header("Text audit (F4)")]
    [SerializeField] private float minTextSize = 24f;   // our design rule at 1280 × 800

    private readonly float[] samples = new float[60];   // the last 60 frame times
    private int index;
    private int count;
    private bool visible;

    private void Awake()
    {
        readout.gameObject.SetActive(false);
    }

    private void Update()
    {
        RecordFrame(Time.unscaledDeltaTime);

        Keyboard keyboard = Keyboard.current;
        if (keyboard != null && keyboard.f3Key.wasPressedThisFrame)
        {
            visible = !visible;
            readout.gameObject.SetActive(visible);
        }
        if (keyboard != null && keyboard.f4Key.wasPressedThisFrame)
        {
            AuditTextSizes();
        }

        if (!visible) return;                           // guard clause: nothing to draw
        ShowReadout();
    }

    // A circular buffer: the newest time replaces the oldest once the array is full.
    private void RecordFrame(float frameTime)
    {
        samples[index] = frameTime;
        index = (index + 1) % samples.Length;           // 59 + 1 wraps back to 0
        if (count < samples.Length) count++;
    }

    private void ShowReadout()
    {
        float total = 0f;
        float worst = 0f;
        for (int i = 0; i < count; i++)
        {
            total += samples[i];
            if (samples[i] > worst) worst = samples[i];
        }
        float average = total / count;
        float fps = 1f / average;
        float memoryMB = Profiler.GetTotalAllocatedMemoryLong() / 1000000f;

        readout.text = $"{fps:0} fps   avg {average * 1000f:0.0} ms   worst {worst * 1000f:0.0} ms   {memoryMB:0} MB";
        readout.color = fps >= targetFps ? Color.green : Color.red;
    }

    // Lists every TextMesh Pro text in the scene smaller than the design rule.
    private void AuditTextSizes()
    {
        int problems = 0;
        TMP_Text[] texts = FindObjectsByType<TMP_Text>(FindObjectsInactive.Include, FindObjectsSortMode.None);
        foreach (TMP_Text text in texts)
        {
            float smallest = text.enableAutoSizing ? text.fontSizeMin : text.fontSize;
            if (smallest < minTextSize)
            {
                Debug.LogWarning($"Text too small ({smallest} px): {text.name}", text);
                problems++;
            }
        }
        Debug.Log($"Text audit: checked {texts.Length} texts, {problems} below {minTextSize} px.");
    }
}

Building for Linux

Steam Deck runs SteamOS, which is based on Linux. Windows games can run through Proton, Valve's compatibility layer, but a native Linux build removes that extra step. Unity can build one from the same project.

Build steps

  1. Open File → Build Profiles, select Linux and switch to it. If it's missing, add Linux Build Support to your Unity install through Unity Hub.
  2. Build into a new folder called Build-Linux.
  3. Check the build folder contains an executable named after your product, plus a _Data folder.

What changes on Linux?

Three portability checks

  1. Save location: persistentDataPath becomes a folder under ~/.config/unity3d/. Our code never hard-codes a path, so this just works.
  2. Path separators: Linux uses / and Windows uses \. Every path in our code is built with Path.Combine, which picks the right one.
  3. Case-sensitivity: on Linux, Photo_1.png and photo_1.png are different files. Code that saves one spelling and loads another works on Windows but fails on Linux. Our file names are always built by the same method, so they always match.

Discuss: which decisions from earlier lessons made our game more portable without us realising it at the time?
