Analysis activity · pairs · 4 min

What kind of tests do you have?

Flick through your test table from Lessons 3–10.

  1. Roughly how long would it take to run all 40 by hand? How often would you realistically do it?
  2. Which tests check how the game feels or looks (only a person can judge), and which check a rule with one right answer?
  3. Find a rule you tested with only one value. What values did you not try?

Tests that check feel, looks and hardware will always need a person. But rules with one right answer, like "captions stop at 60 characters", can be checked by code in milliseconds, as often as you like. That's what unit tests are for.

Choosing test data

Testing a rule with one value proves very little. Good testers choose data deliberately, in three types:

TypeCaption rule: trim, max 60Expected resultWhy test it
Normal"Fog over the valley"UnchangedThe everyday case must work
Normal"   Summit  ""Summit"Spaces typed by accident are common
Boundary60 charactersAll 60 keptOff-by-one errors live at edges, e.g. > written instead of >=
Boundary61 charactersCut to 60The first value that must change
Boundary"" (empty)""The smallest possible input
Invalidnull (no caption at all)""Should never happen, but mustn't crash if it does

You do · 3 min

The journal holds at most 50 photos. In your notebook, list normal, boundary and invalid test data for the rule "the journal is full when it has 50 or more photos". Include the expected IsFull result for each.

Normal: 12 photos → false. Boundary: 0 → false, 49 → false, 50 → true, 51 → true (it shouldn't happen, but the rule uses >= so it still counts as full). Invalid: a negative count can't occur, because a list's count is never below 0. Recognising impossible data is part of choosing test data too.

Testable code

Try writing an automated test for CaptureRoutine from Lesson 4. It needs a screen to capture, a frame to finish drawing, a real folder, the clock and a sound. That's a lot to set up just to check one rule. Compare:

1JournalRules.cs: the rules, now pure
// Recommended filename: JournalRules.cs   (folder: Assets/PhotoJournal/Logic)
using System;
using System.Collections.Generic;

// Pure logic: no Unity, no files, no screen. Same input, same output, every time.
// That makes every method here easy to test automatically.
public static class JournalRules
{
    public const int MaxCaptionLength = 60;     // from the Lesson 2 data dictionary

    public static string CleanCaption(string caption)
    {
        caption = (caption ?? "").Trim();
        if (caption.Length > MaxCaptionLength)
        {
            caption = caption.Substring(0, MaxCaptionLength);
        }
        return caption;
    }

    public static int CountPlaces(IEnumerable<string> locationNames)
    {
        List<string> places = new List<string>();
        foreach (string name in locationNames)
        {
            if (!places.Contains(name))
            {
                places.Add(name);
            }
        }
        return places.Count;
    }

    // "exists" is passed in, so a test can pretend which files exist.
    public static string MakeUniqueFileName(string baseName, Func<string, bool> exists)
    {
        string fileName = baseName + ".png";
        int copy = 2;
        while (exists(fileName))
        {
            fileName = baseName + "_" + copy + ".png";
            copy++;
        }
        return fileName;
    }
}
These are the same algorithms you desk-checked in Lessons 4, 8 and 9. The only new idea is Func<string, bool> exists: a method passed in as a value. The game passes "check the real folder", and a test passes "check this list". The rule doesn't care which.

Writing unit tests

Every unit test follows the same three steps: Arrange the input, Act by calling the method, and Assert what the result must be.

3One test, three steps
public void CleanCaption_NormalText_IsUnchanged()
{
    // Arrange
    string input = "Fog over the valley";
    // Act
    string result = JournalRules.CleanCaption(input);
    // Assert
    Assert.AreEqual("Fog over the valley", result);
}
[Test] tells the Test Runner this method is a test. The name says what's tested, the situation, and the expected outcome, so a failing test explains itself. Assert.AreEqual(expected, actual) fails the test if the two differ.
4Boundary and invalid tests
public void CleanCaption_Exactly60_IsKept()
{
    string sixty = new string('a', 60);
    Assert.AreEqual(60, JournalRules.CleanCaption(sixty).Length);
}

public void CleanCaption_61_IsCutTo60()
{
    string sixtyOne = new string('a', 61);
    Assert.AreEqual(60, JournalRules.CleanCaption(sixtyOne).Length);
}

public void CleanCaption_Null_BecomesEmpty()
{
    Assert.AreEqual("", JournalRules.CleanCaption(null));
}
new string('a', 60) builds a 60-letter string without typing it. Shorter tests like these skip the Arrange/Act/Assert comments, but the three steps are still there.
5Turning a desk check into a test
public void FrameSampler_Lesson10DeskCheck_MatchesByHand()

    Assert.AreEqual(35f, sampler.Average);
    Assert.AreEqual(60f, sampler.Worst);

public void MakeUniqueFileName_TwoExist_AddsThree()
{
    var existing = new List<string> { "photo_20261002_143012.png", "photo_20261002_143012_2.png" };
    string result = JournalRules.MakeUniqueFileName("photo_20261002_143012", existing.Contains);
    Assert.AreEqual("photo_20261002_143012_3.png", result);
}
These are the Lesson 10 and Lesson 4 desk checks, written as code. You worked them out by hand once; now the computer re-checks them every time you run the tests. existing.Contains is passed as exists, so the test pretends those two files are in the folder.

A test that found a bug

What's the average of nothing?

When FrameSampler was first moved out of Lesson 10's script, it didn't have a guard clause on Average. In Lesson 10 that never mattered: a frame was always recorded before the readout. But a boundary test asks a question the game never did: what if no frames have been added yet?

public void FrameSampler_Empty_AverageIsZero()
{
    var sampler = new FrameSampler(4);
    Assert.AreEqual(0f, sampler.Average);
}

Without the guard, the Test Runner reported:

✗ FrameSampler_Empty_AverageIsZero
  Expected: 0
  But was:  NaN
13 passed, 1 failed
0 ÷ 0 has no answer. For decimal numbers (floats), C# gives NaN, "Not a Number", instead of crashing. NaN then spreads silently: 1 ÷ NaN is NaN, so the readout would show "NaN fps". The fix is a guard clause: if (count == 0) return 0f;. After adding it, all 14 tests pass. This is why boundary data matters: the bug was real, but no manual test would have found it, because the game never asks for the average of nothing. Yet.

// Recommended filename: FrameSampler.cs   (folder: Assets/PhotoJournal/Logic)

// The Lesson 10 circular buffer, moved into its own class so it can be tested.
public class FrameSampler
{
    private readonly float[] samples;
    private int index;
    private int count;

    public FrameSampler(int size)
    {
        samples = new float[size];
    }

    public int Count => count;

    public void Add(float frameTime)
    {
        samples[index] = frameTime;
        index = (index + 1) % samples.Length;
        if (count < samples.Length) count++;
    }

    public float Average
    {
        get
        {
            if (count == 0) return 0f;          // guard clause: added after a test failed
            float total = 0f;
            for (int i = 0; i < count; i++)
            {
                total += samples[i];
            }
            return total / count;
        }
    }

    public float Worst
    {
        get
        {
            float worst = 0f;
            for (int i = 0; i < count; i++)
            {
                if (samples[i] > worst) worst = samples[i];
            }
            return worst;
        }
    }
}

// Recommended filename: PlatformLink.cs
using System.Collections.Generic;
using System.IO;
using UnityEngine;

// Connects the journal to whichever platform is running. It never needs to know which one.
public class PlatformLink : MonoBehaviour
{
    [SerializeField] private Journal journal;
    [SerializeField] private int placesNeeded = 3;

    private int lastCount;

    private void Start()
    {
        lastCount = journal.Entries.Count;
        journal.JournalChanged += OnJournalChanged;
        CheckAchievements();                    // counts progress made before achievements existed
    }

    private void OnDestroy()
    {
        journal.JournalChanged -= OnJournalChanged;
    }

    private void OnJournalChanged()
    {
        if (Platform.Current == null) return;   // guard clause: no platform registered

        int count = journal.Entries.Count;
        if (count > lastCount)                  // a photo was added, not deleted
        {
            JournalEntry newest = journal.Entries[count - 1];
            string path = Path.Combine(journal.PhotoFolder, newest.fileName);
            Platform.Current.AddScreenshot(path, newest.locationName);
        }
        lastCount = count;
        CheckAchievements();
    }

    private void CheckAchievements()
    {
        if (Platform.Current == null) return;   // guard clause

        if (journal.Entries.Count >= 1) Platform.Current.UnlockAchievement(Achievements.FirstPhoto);
        if (CountPlaces() >= placesNeeded) Platform.Current.UnlockAchievement(Achievements.ThreeTrails);
        if (journal.IsFull) Platform.Current.UnlockAchievement(Achievements.FullJournal);
    }

    // Counts how many different location names appear in the journal.
    private int CountPlaces()
    {
        List<string> names = new List<string>();
        foreach (JournalEntry entry in journal.Entries)
        {
            names.Add(entry.locationName);
        }
        return JournalRules.CountPlaces(names);     // tested in JournalRulesTests
    }
}

// Recommended filename: DeckReadinessTools.cs
// Developer tools for Lesson 10. F3 shows performance; F4 audits text sizes.
using TMPro;
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.Profiling;

public class DeckReadinessTools : MonoBehaviour
{
    [Header("Performance readout (F3)")]
    [SerializeField] private TMP_Text readout;
    [SerializeField] private float targetFps = 30f;

    [Header("Text audit (F4)")]
    [SerializeField] private float minTextSize = 24f;   // our design rule at 1280 × 800

    private readonly FrameSampler sampler = new FrameSampler(60);   // tested in JournalRulesTests
    private bool visible;

    private void Awake()
    {
        readout.gameObject.SetActive(false);
    }

    private void Update()
    {
        sampler.Add(Time.unscaledDeltaTime);

        Keyboard keyboard = Keyboard.current;
        if (keyboard != null && keyboard.f3Key.wasPressedThisFrame)
        {
            visible = !visible;
            readout.gameObject.SetActive(visible);
        }
        if (keyboard != null && keyboard.f4Key.wasPressedThisFrame)
        {
            AuditTextSizes();
        }

        if (!visible) return;                           // guard clause: nothing to draw
        ShowReadout();
    }

    private void ShowReadout()
    {
        float average = sampler.Average;
        float worst = sampler.Worst;
        float fps = average > 0f ? 1f / average : 0f;
        float memoryMB = Profiler.GetTotalAllocatedMemoryLong() / 1000000f;

        readout.text = $"{fps:0} fps   avg {average * 1000f:0.0} ms   worst {worst * 1000f:0.0} ms   {memoryMB:0} MB";
        readout.color = fps >= targetFps ? Color.green : Color.red;
    }

    // Lists every TextMesh Pro text in the scene smaller than the design rule.
    private void AuditTextSizes()
    {
        int problems = 0;
        TMP_Text[] texts = FindObjectsByType<TMP_Text>(FindObjectsInactive.Include, FindObjectsSortMode.None);
        foreach (TMP_Text text in texts)
        {
            float smallest = text.enableAutoSizing ? text.fontSizeMin : text.fontSize;
            if (smallest < minTextSize)
            {
                Debug.LogWarning($"Text too small ({smallest} px): {text.name}", text);
                problems++;
            }
        }
        Debug.Log($"Text audit: checked {texts.Length} texts, {problems} below {minTextSize} px.");
    }
}
