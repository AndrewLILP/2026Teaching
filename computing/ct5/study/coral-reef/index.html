How the questions are tiered

Every level page carries the same three-tier structure so you can self-select the right challenge level, or work through all three.

Foundation (D–E) — identify, read, recall Core (C) — convert code↔pseudocode, complete a desk-check Extension (B–A) — debug a logic error, design an extension

Outcomes covered

CT5-OPL-01Designs, produces and evaluates algorithms — pseudocode, flowcharts and desk-checks across all four levels.
CT5-THI-01Computational & systems thinking — classifying sequence / selection / iteration; comparing Level 3 and Level 4 as "sense-decide-react" systems.
CT5-DPM-01Iterative design — the Extension-tier design tasks ask students to extend a working algorithm to meet a new requirement.
CT5-DAT-01Data handling — Level 4's multiple sensor readings and unit conversions (inches / mm).

Reading a level page

1
Given code — the VEXcode VR blocks as provided, shown as a styled block panel.
2
Flowchart — terminators, process boxes and decision diamonds for every branch and loop.
3
NSW pseudocode — BEGIN/END, IF/THEN/ENDIF, REPEAT FOREVER/ENDREPEAT, WAIT UNTIL.
4
Python (VEXcode VR) — the pseudocode translated into VEXcode VR's actual Python API, so students see pseudocode → implementation language directly.
5
Desk-check — a partly blank trace table to complete by hand before checking the answer.
6
Questions — Foundation, Core and Extension, each with a reveal-on-demand answer.
