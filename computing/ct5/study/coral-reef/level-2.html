Selection: Sensing Before Acting

This example uses the Distance Sensor on the VR Robot to detect a piece of trash, then the robot will drive to the trash to collect it.

Playground: Coral Reef Cleanup Structure: Sequence + Selection Sensor: FrontDistance
CT5-OPL-01 CT5-THI-01 Selection

Level 2 introduces the Distance Sensor. The robot turns on the spot while repeatedly checking a condition — this is selection: the program's next action depends on whether the Distance Sensor has found an object yet. The wait until block pauses the sequence until that condition becomes true.

2. Flowchart

3. NSW pseudocode

BEGIN
  DRIVE forward 800 mm
  TURN right
  WAIT UNTIL FrontDistance detects an object
  DRIVE forward FrontDistance (in mm)
END
Why this matters: wait until looks like a single instruction in VEXcode, but underneath it behaves like a condition-controlled loop: while the condition is false, the robot keeps turning; the moment it becomes true, the program moves on. That's why the flowchart needs a decision diamond even though the block code doesn't show an explicit IF.

4. Python (VEXcode VR)

In Python, wait until is not its own command — it's written out as the while loop the flowchart already showed. This makes the "hidden" loop from Section 2 visible in the code.

level2_coral_reef_cleanup.py
def main():
    # Drive toward the first approach point.
    drivetrain.drive_for(FORWARD, 800, MM)
    # Start turning continuously (non-waiting command).
    drivetrain.turn(RIGHT)
    # Keep turning until the Distance Sensor finds an object.
    while not front_distance.found_object():
        wait(5, MSEC)
    drivetrain.stop()
    # Drive forward exactly as far as the trash is away.
    drivetrain.drive_for(FORWARD, front_distance.get_distance(MM), MM)

vr_thread(main())
API notes: drivetrain.turn(RIGHT) (no angle argument) is a non-waiting command — it starts turning and immediately lets the next line run, which is why the while loop is needed to keep re-checking the sensor. Compare this to turn_for(...) in Level 1, which waits for itself to finish.

Q7 — Debug. A student changed the program so the wait until block was moved before the turn right block. Explain what would go wrong. (3 marks)

when started
  drive forward for 800 mm
  wait until FrontDistance found an object?
  turn right
  drive forward for FrontDistance in mm mm
Show answer
The robot is not turning while it waits, so unless trash happens to already be directly in front of it, FrontDistance found an object? will never become true and the program will freeze on that line forever (an infinite wait). The turning must happen while the condition is checked, not before.

Q8 — Extend. Design pseudocode for a Level 2b where the robot should give up and stop turning if it completes a full 360-degree turn without finding trash (i.e. add a second exit condition). (4 marks)

Show answer
Accept any pseudocode that tracks accumulated turn angle and combines it with the sensor check, e.g.:
BEGIN
  DRIVE forward 800 mm
  SET angleTurned = 0
  WHILE FrontDistance found an object? = false AND angleTurned < 360 DO
    TURN right 5 degrees
    SET angleTurned = angleTurned + 5
  ENDWHILE
  IF FrontDistance found an object? = true THEN
    DRIVE forward FrontDistance (in mm)
  ENDIF
END
Credit responses that explain why a second condition is needed: without it, a genuine sensor fault would leave the robot turning forever.
