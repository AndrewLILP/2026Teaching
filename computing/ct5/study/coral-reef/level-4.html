1. Designing the exemplar: three checks, one priority order

The key design decision is priority order. On every pass of the loop the robot must ask, in this order:

  1. Am I about to hit the reef boundary? (safety — always checked first)
  2. Is there trash in front of me? (task — checked only if safe)
  3. Otherwise, keep exploring forward. (default behaviour)

This maps onto an IF / ELSE IF / ELSE chain nested inside the Level 3 forever loop:

3. NSW pseudocode

BEGIN
  REPEAT FOREVER
    IF DownEye detects blue THEN
      DRIVE reverse 100 mm
      TURN right (RANDOM(90, 180)) degrees
    ELSE IF FrontDistance found an object THEN
      DRIVE forward FrontDistance (in mm)
    ELSE
      DRIVE forward
    ENDIF
  ENDREPEAT
END
Why this matters: this is nested selection inside iteration — the same shape as Level 4's original Distance Sensing example, but now built entirely from Coral Reef Cleanup concepts. Notice there is only one IF/ELSE IF/ELSE chain: exactly one branch runs per loop, in priority order. This is what makes it a genuine synthesis rather than three separate programs bolted together.

4. Python (VEXcode VR)

Every function call below already appeared in an earlier level's Python code. The only new idea is the if / elif / else chain that decides which one runs on a given pass.

level4_coral_reef_cleanup_exemplar.py
import random

def main():
    while True:
        # Priority 1 (Level 3): protect the robot from the reef boundary.
        if down_eye.detect(BLUE):
            drivetrain.drive_for(REVERSE, 100, MM)
            drivetrain.turn_for(RIGHT, random.randint(90, 180), DEGREES)
        # Priority 2 (Level 2): collect trash when it's found.
        elif front_distance.found_object():
            drivetrain.drive_for(FORWARD, front_distance.get_distance(MM), MM)
        # Priority 3 (Level 1): otherwise, keep exploring forward.
        else:
            drivetrain.drive(FORWARD)
        wait(5, MSEC)

vr_thread(main())
API notes: the elif guarantees only one branch executes per loop pass — if the boundary check is true, Python never even evaluates front_distance.found_object(). This is what makes the priority order in Section 1 actually happen in code, not just in the diagram.

Q6. Explain, in your own words, why the boundary check must be the first condition tested, not the trash check. (2 marks)

Show answer
Driving into the reef is a safety failure that the whole task depends on avoiding; collecting trash is only useful if the robot survives to keep collecting. Testing safety first means it always overrides the task, even if trash happens to be detected at the same moment.
Extension B–A

Q7 — Debug. A student swapped the priority order, checking FrontDistance before DownEye. Explain what could go wrong. (3 marks)

while True:
  if front_distance.found_object():
    drivetrain.drive_for(FORWARD, front_distance.get_distance(MM), MM)
  elif down_eye.detect(BLUE):
    drivetrain.drive_for(REVERSE, 100, MM)
    drivetrain.turn_for(RIGHT, random.randint(90, 180), DEGREES)
  else:
    drivetrain.drive(FORWARD)
Show answer
If trash happens to be right next to the reef boundary, the robot will drive straight toward it — and potentially into the boundary — because the trash-collection branch now runs before the safety check ever gets a chance to fire. Priority order in an IF/ELIF chain is a genuine design decision, not just a stylistic choice.

BEGIN
  REPEAT FOREVER
    CLEAR display
    IF DownEye detects blue THEN
      OUTPUT "Avoiding boundary"
      DRIVE reverse 100 mm
      TURN right (RANDOM(90,180)) degrees
    ELSE IF FrontDistance found an object THEN
      OUTPUT "Collecting trash"
      DRIVE forward FrontDistance (in mm)
    ELSE
      OUTPUT "Exploring"
      DRIVE forward
    ENDIF
  ENDREPEAT
END
Credit responses that note the OUTPUT lines don't affect the IF conditions or movement blocks at all — they're purely observational, which is exactly the role the original Level 4 print blocks played.
