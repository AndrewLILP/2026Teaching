Identifying and Defining

Foundation tier (D-E)

  1. Q1. In the coin collecting game, which of these is an input?

    Answer: The player pressing the W key to move

    Correct! Pressing a movement key sends new data into the game, so it's an input.

  2. Q2. Which of these is an output in the coin game?

    Answer: The coins-collected counter shown on screen

    Correct! The coins-collected number shown on screen is data the system displays to the player — an output.

  3. Q3. Games and simulations have evolved partly because of changing needs in society and industry. Which of these is an example of this?

    Answer: A simulation is used to train pilots safely before they fly a real plane

    Correct! Aviation adopted flight simulators so pilots could safely practise before flying a real plane — a real industry need driving the technology.

  4. Q4. Checking “IF the player touches a coin THEN collect it” is an example of which logic structure?

    Answer: Branching

    Correct! An IF…THEN check is branching — the program takes a different path depending on whether the condition is true.

  5. Q5. The health bar ticking down, second after second, while the player plays is best described as which logic structure?

    Answer: Iteration

    Correct! Repeating the same “reduce health slightly” step over and over is iteration.

  6. Q6. Which of these is a non-functional requirement for the coin game?

    Answer: The game must run smoothly without lag

    Correct! This describes a quality of the game (performance) rather than a specific feature it must do — that's non-functional.

  7. Q7. Which piece of data would the game need to store while the player is playing?

    Answer: The number of coins collected so far

    Correct! The game must keep track of the number of coins collected so far so it can check when to spawn the star.

  8. Q8. When designing the coin game's world and characters, thinking carefully about players with disability is an example of what?

    Answer: Considering diverse perspectives in design

    Correct! The syllabus asks designers to consider diverse groups — including people with disability — when designing games.

  4. Q4. In Level 2, coins spawn randomly, many at once. Which logic structure would most likely place each coin's position?

    Answer: A loop (iteration) that runs once for each coin

    Correct! A loop (iteration) runs the “place a coin at a random position” steps once for each coin needed.

  5. Q5. Type-in: In IPO (Input–Process–Output) terms, what is the one-word term for “data that enters a system”?

    Answer: input

    Answer: Input: player walks into a coin → Expected output: coin count increases by 1

  7. Q7. Describing how the coin count moves from the game's logic to the on-screen UI display is best described as:

    Answer: Transmission

    Correct! Moving data from one part of a system to another (logic to UI) is transmission.

  8. Q8. Type-in: What term describes a requirement that focuses on a quality of a system (such as performance or reliability) rather than a specific feature it must do?

    Answer: non-functional

    Accepted answer(s): non-functional, non functional, nonfunctional, non-functional requirement

  9. Q9. Which of these is an example of an object-oriented (OOP) feature that could describe a “Coin” in the game?

    Answer: A class called Coin with properties like position and value

    Correct! A class groups related data (like position and value) and behaviour together — that's an OOP feature.

Extension tier (B-A)

  1. Q1. Which best describes the difference between Level 1 and Level 2's coin-spawning logic?

    Answer: Level 1 places coins using a fixed sequence; Level 2 uses a loop with randomisation

    Correct! Fixed positions can be placed once in order (sequence); random, many-at-once placement needs a loop that repeats the “place a coin randomly” step.

  2. Q2. Which non-functional requirement matters most for a fast-paced game like this one?

    Answer: Responsive controls with minimal input lag

    Correct! In a fast-paced game, controls feeling responsive (low input lag) is a critical quality-of-experience requirement.

  3. Q3. A test case for “a star appears after 20 coins” needs to check which of the following?

    Answer: That a star does NOT appear at 19 coins, and DOES appear at 20

    Correct! Good test cases check the boundary — confirming the star does NOT appear too early and DOES appear exactly at 20.

  4. Q4. Which design choice best reflects an ethical, inclusive approach for this coin game?

    Answer: Offering an adjustable timer/health-drain speed so players with different needs can play comfortably

    Correct! Letting players adjust settings like timer/health-drain speed helps the game suit a wider range of needs and abilities.

  5. Q5. Type-in: What one-word term describes a person's right to control their own personal information, such as their photo or data?

    Answer: privacy

    Accepted answer(s): privacy

  6. Q6. Type-in: What one or two-word term describes a description of how a specific type of user interacts with a system — e.g. “a new player opens the game and plays Level 1 for the first time”?

    Answer: use case

    Accepted answer(s): use case, use cases

  7. Q7. A hospital uses simulation software to train surgeons before real operations, and a mining company uses simulation software to test how a new tunnel design will behave. What is the best explanation for why these industries have adopted this kind of software?

    Answer: It allows people to safely test high-risk or costly scenarios before committing to them in the real world

    Correct! Both examples let people safely test high-risk, high-cost, or dangerous scenarios before committing to them in the real world — that's the underlying reason simulation has spread across so many industries.

Researching and Planning

Foundation tier (D-E)

  1. Q1. A traffic light system uses a predefined algorithm to decide exactly when the lights change. What does this show?

    Answer: A predefined algorithm can control a real-world computer component

    Correct! The traffic light's behaviour is controlled by a set, predefined algorithm — a clear example of algorithms controlling components.

  2. Q2. Which of these best describes Virtual Reality (VR)?

    Answer: Fully immersing the user in a computer-generated environment, usually with a headset

    Correct! VR replaces the user's view of the real world entirely with a simulated environment.

  3. Q3. The rules for how many coins are needed to spawn the star, and how health drains over time, are part of the coin game's:

    Answer: Mechanics

    Correct! The rules and systems that govern how the game actually works — like coin thresholds and health drain — are its mechanics.

  4. Q4. Which data type would best store the value of “coins collected”?

    Answer: A whole number (integer)

    Correct! Coins collected is always a whole number — an integer is the appropriate data type.

  5. Q5. Which flowchart shape represents a decision (branching) step, such as “IF player touches coin”?

    Answer: A diamond

    Correct! The diamond shape shows a decision point in a flowchart.

  6. Q6. Changing the coin-spawning algorithm from “always the same position” (Level 1) to “random position” (Level 2) is an example of:

    Answer: Modifying an existing algorithm

    Correct! Taking an existing algorithm (fixed-position spawning) and changing part of its logic is exactly what “modifying an algorithm” means.

  7. Q7. Which of these is a cyber safety consideration when planning an online multiplayer version of the coin game?

    Answer: Making sure players can't see or share each other's personal information through chat

    Correct! Protecting players' personal information from being exposed through in-game features is a core cyber safety consideration.

  8. Q8. Which of these is an example of data the coin game might reasonably collect about a player?

    Answer: The player's playtime and high score

    Correct! Playtime and score are gameplay-related data a game would reasonably track.

Core tier (C)

  1. Q1. When choosing between two possible designs for the coin game's UI, what should the team do?

    Answer: Generate both alternatives and evaluate them against the requirements before picking one

    Correct! Generating alternative designs and evaluating them against the requirements is how a preferred design is properly selected.

  2. Q2. Type-in: What one or two-word term describes manually working through an algorithm step-by-step to check it behaves correctly, before it's coded?

    Answer: desk check

    Accepted answer(s): desk check, desk checking, deskcheck

  3. Q3. A city-planning simulation lets councils test new road designs before any building work starts. What does this show about simulations?

    Answer: Simulations can help solve real-world problems by safely testing outcomes in advance

    Correct! This is a clear example of a simulation solving a real-world problem by letting people test outcomes before committing resources.

  4. Q4. Giving the player a clear, consistent sound and animation every single time they collect a coin is an example of which design principle?

    Answer: Consistency (clear, predictable feedback)

    Correct! Giving the same clear feedback every time an action happens is the design principle of consistency.

  5. Q5. Type-in: What is the general computing term for a variable that stores a whole number, with no decimal point (e.g. coins collected)?

    Answer: integer

    Accepted answer(s): integer

  6. Q6. A playtester says the coin game's controls feel confusing the first time they play. Which quality is this feedback mainly about?

  7. Q7. Before collecting any player data (such as high scores), a responsible developer should first decide:

    Answer: What data will be collected, who owns it, and how it will be protected

    Correct! Responsible data collection means deciding in advance what is collected, who owns it, and how it will be kept secure.

  8. Q8. Type-in: What is the common short term (often just two letters) for computer systems designed to mimic intelligent behaviour, such as an opponent that adapts to the player?

    Answer: ai

    Accepted answer(s): ai, artificial intelligence

  9. Q9. The team decides to change the coin-spawning algorithm from “always the same position” to “random position”. What should they do before writing any code?

    Answer: Update the algorithm's design (e.g. its flowchart or pseudocode) to reflect the new logic

    Correct! An algorithm's design should be updated and represented (e.g. in a flowchart or pseudocode) before jumping straight into code.

Producing and Implementing

Foundation tier (D-E)

  1. Q1. IPO charts, decision trees, flowcharts and pseudocode are all examples of:

    Answer: Program-development support tools used to plan a solution before coding

    Correct! These are all tools used to plan and represent a solution's logic before it's turned into code.

  2. Q2. In the pseudocode line IF player touches coin THEN collect it, which logic structure is being represented?

    Answer: Branching

    Correct! An IF…THEN line represents a decision — branching.

  3. Q3. Which data type would be most appropriate for storing a player's chosen character name?

    Answer: Text (a string)

    Correct! A player's name is made of letters, so a text/string data type is appropriate.

  4. Q4. Why do developers add comments and documentation to their code?

    Answer: To make the code easier to read, understand and maintain later

    Correct! Comments and documentation help other developers (or the same developer later) understand what the code does and why.

  5. Q5. In programming, what is a “variable”?

    Answer: A named piece of storage that can hold a value which may change while the program runs

    Correct! A variable is a named storage location whose value can change as the program runs.

  6. Q6. What does it mean to “plan and manage a project using an iterative approach”?

    Answer: Repeating cycles of building, testing and improving the solution over time

    Correct! An iterative approach means repeating cycles of build → test → improve, rather than finishing everything in one pass.

  7. Q7. In event-driven programming, what is an “event”?

    Answer: Something that happens, like the player pressing a key, that the program can respond to

    Correct! An event is something that happens — like a key press — that the program listens and responds to.

  8. Q8. What is the difference between UI and UX?

    Answer: UI is what the player sees and interacts with; UX is the overall experience and feeling of using it

    Correct! UI (User Interface) is the visual/interactive elements; UX (User Experience) is the overall feeling and ease of using the whole product.

  8. Q8. Type-in: What type of error occurs when code doesn't follow the rules of the programming language, such as a missing bracket?

Extension tier (B-A)

  1. Q1. In a simple simulated environment, each cell's next state is decided by looking at the states of its neighbouring cells (for example, a cell “turns on” if enough neighbours are “on”). What determines each cell's next state?

    Answer: The states of its neighbouring cells, applied through a rule

    Correct! This is how a 2D cellular simulation works — each cell's next state is calculated from its neighbours' current states.

    Answer: Testing how changing a variable's value affects the program's behaviour

    Correct! Deliberately changing a variable and observing the effect is exactly how a developer explores and tunes a program's behaviour.

  4. Q4. A developer adds an extra value to the array storing coin positions, then reruns the game and sees an extra coin appear in the world. What does this show?

    Answer: That modifying an array of data can directly change what appears in the game

    Correct! This shows how changing the contents of an array (adding a coin position) directly affects the game's behaviour — an extra coin appears.

  7. Q7. This pseudocode is meant to increase the coin count by 1 every time the player touches a coin, and show the star once 20 coins are collected. One line has a logic error. Click the line number that contains it.

  1. Q1. Checking that the coin game actually does what it's supposed to — like making the star appear at 20 coins — is testing against which type of requirement?

    Answer: A functional requirement

    Correct! Checking that a specific feature/behaviour actually works is testing against a functional requirement.

  2. Q2. What does it mean to “trace” an algorithm?

    Answer: Following it through step by step to check how it behaves

    Correct! Tracing means working through an algorithm's steps in order to check what it actually does.

  3. Q3. “Testing functionality” mainly means checking:

    Answer: Whether the game does what it's supposed to do

    Correct! Testing functionality means checking that the game's features actually behave as intended.

  4. Q4. Which of these is an example of an ethical or legal consideration when evaluating a finished game?

    Answer: Checking whether any copyrighted music was used without permission

    Correct! Using copyrighted material without permission is a clear legal and ethical issue to check for.

  5. Q5. Checking that the coin game runs smoothly without lag is testing against which type of requirement?

    Answer: A non-functional requirement

    Correct! Smooth performance is a quality of the system, which makes it a non-functional requirement.

  6. Q6. Which of these is an example of a career in game and simulation development?

    Answer: Game designer

    Correct! Game designer is a recognised career within game and simulation development.

  7. Q7. What is a “test case”?

    Answer: A specific input paired with its expected output, used to check a requirement

    Correct! A test case pairs a specific input with the output that's expected, to check the requirement is met.

  8. Q8. Which of these is a basic cybersecurity check to do when evaluating a finished game?

    Answer: Checking that no personal player data is accidentally exposed or leaked

    Correct! Making sure personal data isn't accidentally exposed is a fundamental cybersecurity check.

    Answer: No — non-functional requirements also need to be evaluated, not just functional ones

    Correct! A complete evaluation checks both functional AND non-functional requirements — stopping at functional alone leaves qualities like performance and accessibility unchecked.

  3. Q3. Trace this pseudocode by hand:
    SET coinsCollected TO 0
    REPEAT 3 TIMES
        SET coinsCollected TO coinsCollected + 1
    END REPEAT
    What is the value of coinsCollected after this code finishes running?

    Answer: 3

    Correct! Starting at 0, the loop adds 1 three times (0→1→2→3), so coinsCollected ends at 3.

  7. Q7. A tester finds that the coin game meets all its functional requirements (coins increase count, star appears at 20, level resets under 20% health), but players report the game “feels laggy” on some devices. What is the best next evaluation step?
