From Bug Report to Fix: A Real Iteration Log

Five real bugs, five real fixes, from an actual browser-based teaching resource. No cleaned-up textbook examples — the real bug reports, root causes and fixes, as they happened.

Artefact: Dice & Chance (MA4-PRO-C-01) Outcome: CT5-DPM-01 5 levels
CT5-DPM-01 Iterative process Real-world debugging

Dice & Chance is a real browser-based probability teaching resource, built around two dice games: Push Your Luck (a banked-points game) and Dice Cricket (a batting simulation). Every bug in this series is a genuine build-test-fix cycle the resource actually went through — not a hypothetical exercise.

Outcome CT5-DPM-01 describes an iterative process with five stages: Define → Plan → Design → Develop → Evaluate. Each level in this series names exactly which stage(s) broke down to cause that bug, and which stage caught it. By Level 5, every stage will have appeared at least once.

How each level works

Every level follows the same six-part structure, mirroring how the bugs were actually found and fixed:

1. Bug report 2. Investigate (hands-on) 3. Root cause 4. The fix 5. Proving the fix 6. Questions

Every bug report is a real symptom, not a diagnosis — none of them name the actual cause. Finding the cause, and then proving the fix actually worked rather than just eyeballing it, is the core skill this whole case study is built around. Each "Investigate" section gives a real, reproducible way to trigger the bug yourself — usually a one-line browser console command — rather than just reading about it.

Why this matters: none of these five bugs were caused by an obvious typo. Every one was valid code doing exactly what it was told, producing a result nobody intended. That's the gap between "my code has an error" and "my code has a bug" — and closing that gap is what the Evaluate stage of CT5-DPM-01 is for.

The five levels

LEVEL 1

Magic Numbers

A one-line change request — "10 rounds instead of 5" — exposes a value hardcoded into six separate places.

Plan & Develop LEVEL 2

Defensive Programming

"I need to hit refresh to play again." A single unguarded localStorage call silently kills everything downstream of it.

Develop & Evaluate LEVEL 3

Native vs Custom UI

An unstyled, sometimes-blocked confirm() dialog reveals what happens when the browser draws part of your interface for you.

Design & Develop LEVEL 4

CSS Cascade & Specificity

Buttons render as blank white boxes — not broken, just white text on white, because of how the browser resolves conflicting CSS rules.

Develop & Evaluate LEVEL 5 · FINAL

Box Model & Display

Correct percentages, invisible bars. A <span> quietly ignores its own width — and the series closes with a full recap connecting all five bugs back to the DPM-01 cycle.
