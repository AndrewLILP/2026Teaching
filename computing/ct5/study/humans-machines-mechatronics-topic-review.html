📋 The automatic door — quick reference

You don't need to memorise these details — refer back here any time. The questions are testing computing theory, not your memory of the door's history.

Purpose
To open and close a doorway automatically so people can pass through without using their hands, especially while carrying items or using a wheelchair.
Sensor (input)
Checks continuously whether a person is within range of the doorway.
Actuator (output)
A motor that physically opens or closes the door.
Core decision logic
Person detected within range? Yes → motor opens the door. No → door stays closed. The sensor then loops back to checking.
Key milestones
1st century AD — Heron of Alexandria's automaton (fixed reaction, no sensor). 1931 — Stanley Works' photoelectric door (freed waitstaff's hands). 1954 — mat-actuated door (cheaper, more reliable than photoelectric). 1970s — motion/infrared sensors (accessibility for wheelchair users).
User cases
A customer carrying a loaded tray walks toward the door. A wheelchair user approaches from the side. Someone stands nearby without intending to enter.
Functional requirement example
A shopping trolley with no person attached passes through → door opens anyway, because the sensor can't distinguish a trolley from a person. Power outage → door defaults to manual push-open.
Non-functional requirement examples
Reliability (must not fail during a fire evacuation). Accessibility (must meet disability access standards). Durability (tens of thousands of open/close cycles). Response time (opens within about one second).

🧩 Hands-on example — VEXcode VR: Coral Reef Cleanup

Three versions of the same task, each adding one new capability. Some questions below reference this pseudocode directly — you don't need to memorise it, just refer back here.

Level 1 — fixed sequence

Drives a fixed distance toward a piece of trash, then turns a fixed amount to face the next piece. No sensor is used.

BEGIN
    DRIVE forward 800 mm
    TURN right 90 degrees
END

Level 2 — reacts to a sensor

Drives to the first piece of trash, then turns until the Distance Sensor (FrontDistance) detects an object, then drives exactly that measured distance.

BEGIN
    DRIVE forward 800 mm
    REPEAT
        TURN right
    UNTIL FrontDistance detects object
    SET distanceToTravel TO FrontDistance
    DRIVE forward FOR distanceToTravel mm
END

Level 3 — loops and avoids a boundary

Drives forward continually to collect trash. The Down Eye Sensor (DownEye) watches for the reef's blue boundary; when detected, the robot backs up and turns a random amount so it doesn't repeat the same path.

BEGIN
    WHILE task is running
        DRIVE forward
        WAIT UNTIL DownEye detects blue
        DRIVE reverse 100 mm
        SET turnAmount TO RANDOM(90, 180)
        TURN right FOR turnAmount degrees
    ENDWHILE
END
