Packing the wagon in pseudocode

Yesterday you worked out what a trail game tracks. Today you decide exactly what your program will track, and plan the loop that changes it — all before opening Grok Learning.

Warm-up

Why plan before you code?

It's tempting to open Grok Learning and start typing. But a trail game has moving parts that interact — food affects health, health affects how far you can travel, distance decides whether you win. Get the plan wrong and you'll spend Lesson 3 debugging a design problem instead of a code problem.

Today has one job: turn your brief from Lesson 1 into a concrete state design and a pseudocode plan for the day-by-day loop.

Concept

One day, mapped out

Every day in the game follows the same three-part shape. This is true no matter what your state looks like.

Input

The player is asked for a choice — pace, rations, or which trail feature to deal with.

→
Process

The state updates: resources drop, distance increases, and there's a chance a random event fires.

→
Output

The console tells the player what happened — new totals, and any event that occurred.

Design

Designing the state

Your brief needs food, health, wagon condition, and distance travelled — at minimum. In Python, the natural way to group related values under one name is a dictionary: a set of key/value pairs, where each key is a label and each value is the data behind it.

Example A dictionary for a simpler system — a pet's stats — to show the pattern before you apply it to the wagon: 
pet = {
    "name": "Rex",
    "hunger": 80,
    "happiness": 65
}
Read pet["hunger"] as "the value stored under the key hunger, inside the dictionary pet."

Your state dictionary will follow the same pattern, just with different keys. Every value that can change over the course of the game belongs inside it — nothing important should live outside the dictionary as a separate loose variable.

Plan

Pseudocode the loop

Before writing Python, plan the loop in NSW pseudocode. This is a minimal version — your own will have more state and at least one random event, but the shape is the same.

Pseudocode

1  BEGIN
2    SET food TO 100
3    SET health TO 100
4    SET distance TO 0
5    SET daysPassed TO 0
6
7    WHILE distance < 2000 AND food > 0 AND health > 0
8      DISPLAY "Day " + daysPassed
9      INPUT playerChoice
10     SET food TO food - 10
11     SET distance TO distance + 20
12     SET daysPassed TO daysPassed + 1
13   ENDWHILE
14
15   IF distance >= 2000 THEN
16     DISPLAY "You made it to the coast!"
17   ELSE
18     DISPLAY "The journey ends here."
19   ENDIF
20 END

Notice the WHILE condition checks three things at once — the loop only keeps running while the party hasn't arrived and hasn't run out of food and hasn't run out of health. This is the guard that decides whether the game is still playable.

Bridge

Pseudocode → Python

Here's that same plan translated into Python, using a state dictionary instead of loose variables. You won't type this yet — Lesson 3 is where the real build starts.

Pseudocode 
SET food TO 100
SET distance TO 0

WHILE distance < 2000
      AND food > 0
  DISPLAY "Day " + daysPassed
  INPUT playerChoice
  SET food TO food - 10
  SET distance TO distance + 20
ENDWHILE
Python 
state = {
    "food": 100,
    "distance": 0
}

while state["distance"] < 2000 \
      and state["food"] > 0:
    print(f"Day {state['days_passed']}")
    choice = input("What will you do? ")
    state["food"] -= 10
    state["distance"] += 20
Note: state["food"] -= 10 means the same thing as state["food"] = state["food"] - 10. You'll see both styles — -= is just shorter.

Try it together

As a class, trace what state["food"] equals after 3 days pass, starting from 100 and losing 10 a day with no events. Then discuss: what should happen in the code the moment state["food"] reaches 0? Should the loop keep running?

Vocabulary

Words you'll need this unit

Click each card to flip it.

Dictionary Show definition
A Python data structure that stores values under named keys, written as {"key": value}. Ideal for grouping related state under one variable.
Key / value pair Show definition
One entry in a dictionary — the key is the label (e.g. "food"), the value is the data stored under it (e.g. 100).
Iteration Show definition
One full pass through a loop's body — in this game, one iteration of the loop represents one day.
Condition Show definition
A statement that evaluates to true or false, used to control whether a loop keeps running or a branch executes.
Pseudocode Show definition
A structured, language-independent way of planning an algorithm's logic before committing to a specific programming language's syntax.
Guard Show definition
A condition that protects a loop or function from continuing in an invalid state — here, the loop's guard stops play once food or health hits zero.

How this lesson is graded

This lesson's evidence sits mainly against CT5-DPM-01 (applying iterative processes) — specifically, how complete and workable your state design and pseudocode plan are before any code exists.

A

Your state design anticipates future sprints (event flags, wagon condition tiers) and your pseudocode's guard condition is airtight — no way to loop forever or exit early by accident.

B

Your state design covers every requirement in the brief with sensible starting values, and your pseudocode correctly plans where a random event would slot in.

C

Your state design covers food, health, wagon condition, and distance, and your pseudocode includes a working guard condition on the loop.

D

Your state design lists at least three values the game needs to track, and you've attempted a loop in pseudocode.

E

You can name at least one value your game needs to track and describe, in plain English, what should happen each day.
