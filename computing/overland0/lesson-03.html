Warm-up

From plan to code

You already have a state design and a pseudocode plan from Lesson 2. Sprint A turns that plan into working Python — nothing fancy yet, no random events (that's Sprint B in Lesson 4). By the end of today, your wagon should be able to travel, run out of food, and stop.

Step 1

Set up the state

In a new Grok Learning file, start with your state dictionary. Use your own keys from Lesson 2's Project Notebook entry — this example uses a minimal version.

STEP 1 Create the state dictionary 
state = {
    "food": 100,
    "health": 100,
    "distance": 0,
    "days_passed": 0
}
Every value that changes over the course of the game lives inside state. Nothing important should exist as a separate loose variable outside it — that's the whole point of designing the dictionary in Lesson 2.
Step 2

Build the day loop

Now add the loop itself, straight from your Lesson 2 pseudocode.

STEP 2 Add the guarded while loop
+ NEW THIS STEP
state = {
    "food": 100,
    "health": 100,
    "distance": 0,
    "days_passed": 0
}

while state["distance"] < 2000 and state["food"] > 0:
    print(f"Day {state['days_passed']}: "
          f"{state['distance']}km travelled, "
          f"{state['food']} food remaining")
    state["food"] -= 10
    state["distance"] += 20
    state["days_passed"] += 1

if state["distance"] >= 2000:
    print("You made it to the coast!")
else:
    print("The journey ends here.")
Run this now. It should print one line per day, counting distance up and food down, then stop with a win or a loss message. If it never stops, check your while condition against Lesson 2's pseudocode — a wrong comparison operator is the most common reason a loop refuses to end.
Step 3

Extract a function

Right now, every line lives inside the loop. That's fine for four lines — it won't be fine once Lesson 4 adds random events on top. Move the travel logic into its own function so the loop stays readable as it grows.

STEP 3 Define and call travel()
+ NEW THIS STEP
def travel(state):
    """Advance the party by one day: spend food, gain distance."""
    state["food"] -= 10
    state["distance"] += 20
    state["days_passed"] += 1
    return state

while state["distance"] < 2000 and state["food"] > 0:
    print(f"Day {state['days_passed']}: "
          f"{state['distance']}km travelled, "
          f"{state['food']} food remaining")
    state = travel(state)

if state["distance"] >= 2000:
    print("You made it to the coast!")
else:
    print("The journey ends here.")
travel takes the whole state dictionary as a parameter, changes it, and returns the updated version. The loop calls it with state = travel(state) — the function doesn't need to know anything about printing or checking the ending, just about moving one day forward. That separation is what makes Lesson 4's random events easy to add without rewriting this function.
Concept

Guard clauses

A guard clause is a check at the top of a function that exits early if something would make the rest of the function invalid. You'll need one shortly, once eating or resting becomes a player choice rather than something that happens automatically.

Pseudocode 
FUNCTION eat(state, amount)
  IF state.food <= 0 THEN
    DISPLAY "No food left to eat."
    RETURN state
  ENDIF
  SET state.food TO state.food + amount
  RETURN state
ENDFUNCTION
Python 
def eat(state, amount):
    if state["food"] <= 0:
        print("No food left to eat.")
        return state
    state["food"] += amount
    return state
Note: the guard is the if block at the top of the function, before the "real" work happens. Guarding first — rather than wrapping the real work in an else — keeps the normal case unindented and easy to read.

Vocabulary

Words you'll need this unit

Click each card to flip it.

Function Show definition
A named, reusable block of code that performs one clear job, defined once with def and called wherever it's needed.
Parameter Show definition
A named input a function expects — state in def travel(state): is a parameter. The value passed in when the function is called is the argument.
Return value Show definition
The result a function sends back to wherever it was called, using return. Without it, changes made inside the function are lost when it ends.
Guard clause Show definition
An early check at the top of a function that exits before the main logic runs, if that logic would otherwise be invalid.
Modularity Show definition
Breaking a program into separate, focused pieces (like functions) so each can be understood, tested, and changed on its own.
f-string Show definition
A Python string prefixed with f that lets you embed variables directly inside { }, e.g. f"Day {days}", instead of joining pieces with +.

How this lesson is graded

This lesson's evidence sits mainly against CT5-DPM-01 (developing, testing and implementing algorithms) — specifically, whether your loop and functions actually run correctly and match your Lesson 2 plan.

A

Your code is technically concise — no repeated logic, functions are single-purpose, and a second function with a genuine guard clause runs correctly on the first attempt after debugging.

B

Your loop, state, and travel() function all run correctly, and you've extended travel() with an extra rule of your own that works as intended.

C

Your loop runs, correctly updates state each day, and stops under the right conditions; travel() is implemented as a working function.

D

Your loop runs and prints something each day, though it may not stop correctly or may still have logic inside the loop rather than in a function.

E

You can run the starter code and describe, in plain English, what each line is doing.
