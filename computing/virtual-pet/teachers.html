Learning Intentions & Success Criteria

One Learning Intention and a short set of Success Criteria for each lesson pair currently built in World 1. Each pair also lists the CT5 outcome codes it evidences, matching the tags shown on the student-facing page itself.

Lessons 1–2 — Meet the Virtual Pet Investigating & Researching / Identifying & Defining

Learning Intention

We are learning to analyse an existing computing solution and identify the systems-thinking concepts — attributes, variables, and critical values — that make it work.

Success Criteria

  • I can identify the attributes, variables and critical values in an existing pet system.
  • I can explain what clamping is and why a variable needs it.
  • I can read simple MakeCode Arcade blocks and match them to the equivalent NSW pseudocode.

Lessons 3–4 — Define Your Pet Brief Identifying & Defining / Researching & Planning

Learning Intention

We are learning to write a specific, testable design brief and translate a threshold condition into NSW-format pseudocode.

Success Criteria

  • I can write a brief with a defined concept, three core stats, and testable win and lose conditions.
  • I can write an IF...THEN...ENDIF pseudocode block for a threshold reaction.
  • I can explain why a brief needs to be specific rather than vague, using my own example.
CT5-DPM-01 CT5-THI-01
Lessons 5–6 — Planning the Action Loop Researching & Planning

Learning Intention

We are learning to plan event-driven and continuous logic together, and to choose and justify a custom attribute for our design.

Success Criteria

  • I can distinguish between event-driven logic and continuous logic, with an example of each.
  • I can write full two-part pseudocode (an action plus a drift rule) for an attribute.
  • I can justify my choice of custom stat and plan how it interacts with my three core stats.

Lessons 7–8 — Build the Sprite & Variables Producing & Implementing

Learning Intention

We are learning to translate a written algorithm into working MakeCode Arcade blocks.

Success Criteria

  • I can declare and initialise variables to match my design brief.
  • I can build an on start script that sets every variable to its correct starting value.
  • I can run my project and confirm it produces the result my pseudocode predicted.
CT5-OPL-01 CT5-THI-01
Lessons 9–10 — Feed & Play Actions Producing & Implementing

Learning Intention

We are learning to build and test event-driven actions in isolation, including an action that changes more than one variable.

Success Criteria

  • I can build an event block that changes and correctly clamps a variable.
  • I can test an action on its own and explain what an unexpected result tells me.
  • I can explain how a trade-off action creates a genuine decision for the player.
CT5-OPL-01 CT5-THI-01
Lessons 11–12 — Sleep & the Forever Loop Producing & Implementing

Learning Intention

We are learning to build a continuous loop that manages multiple attributes at once and checks a lose condition automatically.

Success Criteria

  • I can build a forever loop that changes several variables on a timer.
  • I can place a conditional check inside a loop so it runs continuously rather than once.
  • I can design a temporary test for logic that would otherwise take too long to observe directly.
CT5-OPL-01 CT5-THI-01
Lessons 13–14 — Status Display & Your Custom Stat Producing & Implementing

Learning Intention

We are learning to design and build a user interface that communicates a system's internal state to the user, and to finish an attribute to a written specification.

Success Criteria

  • I can use a fast-running update block to build a responsive, continuously updating display.
  • I can make a sprite visually respond to a variable crossing a threshold.
  • I can complete an event-driven and/or reactive custom attribute to match my own specification.
