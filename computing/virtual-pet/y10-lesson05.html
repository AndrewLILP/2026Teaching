Building the Base Class

The starter project already gives you a working Player, complete with movement and interaction detection — you don't rebuild that. Producing & Implementing

Sprint 1 — Five Steps

Work through these steps in order. Test after each one — don't move on until the current step behaves correctly.

1
Build the Pet GameObject
Scene Setup

Import your curated model from the Asset Store shortlist and create a Pet GameObject from it. Add a Sphere Collider or Box Collider sized to a comfortable "reach" distance around it, and tick Is Trigger — this same collider will detect both the player's interaction key and their proximity for showing UI buttons in Step 4.

Add a child Canvas — a World Space canvas positioned above the pet works well — containing a Slider for hunger, and a TextMeshPro – Text (UI) element for status text.

2
Script the Base Class
Class Setup

Attach a new script to the Pet GameObject and save it as Pet.cs. Declare your fields as [SerializeField] private, using the starting values from your Stat System section, and add a public read-only property for each one so other scripts can read the current value without being able to change it directly:

using UnityEngine;
using System;

public class Pet : MonoBehaviour, IInteractable
{
    [SerializeField] private string petName = "Fido";
    [SerializeField] private int hunger = 50;
    [SerializeField] private int social = 50;
    [SerializeField] private bool alive = true;

    public int Hunger => hunger;
    public int Social => social;
    public bool Alive => alive;

    public event Action OnStatChanged;
}

public int Hunger => hunger; is a read-only property — it looks like a variable to anything reading it, but there's no way to write back through it. This is exactly the "narrow public doorway" you were asked to watch for in Lesson 1–2: private data, with deliberate, limited outside access.

3
Write Feed(), Play() & Clean()
Methods

Add Interact() and Feed() below your fields, following the guard-clause shape from your Pet Brief exactly:

Structured English 
FUNCTION Interact()
  CALL Feed()

FUNCTION Feed()
  IF NOT alive THEN
    RETURN
  END IF
  SET hunger TO hunger + 20, max 100
  EMIT StatChanged
C# 
public void Interact()
{
    Feed();
}

private void Feed()
{
    if (!alive) return;
    hunger = Mathf.Min(100, hunger + 20);
    OnStatChanged?.Invoke();
}

Now write Play() and Clean() yourself, as public methods (not called through Interact() — you'll see why in Step 4), in exactly the same shape: guard clause first, then the stat change from your Stat System, then OnStatChanged?.Invoke(); last.

4
Proximity UI & Buttons
Triggers

IInteractable only guarantees one method, Interact() — that's what the player's interact key calls, and on your Pet it's wired to Feed(). Play() and Clean() need their own separate trigger: a UI panel with buttons, shown only when the player is close by.

private void OnTriggerEnter(Collider other)
{
    if (other.CompareTag("Player"))
        petUIPanel.SetActive(true);
}

private void OnTriggerExit(Collider other)
{
    if (other.CompareTag("Player"))
        petUIPanel.SetActive(false);
}

Add a PlayButton and CleanButton to your Canvas, inside a panel GameObject you drag into the petUIPanel field in the Inspector. Select each button, and in its On Click () list in the Inspector, drag the Pet GameObject in and choose Pet > Play() or Pet > Clean(). No code is needed for the click itself — wiring a UnityEvent in the Inspector is the C# equivalent of connecting a signal in Godot's editor.

Test it — walk toward the Pet and confirm the panel appears; walk away and confirm it disappears. Click each button and confirm the correct stat changes.

5
Update the UI from the Event
UI Binding

Your bars and TextMeshPro text shouldn't be set manually inside every method — that's what OnStatChanged is for. Create a second script, PetUI.cs, attached to your Canvas:

using UnityEngine;
using UnityEngine.UI;
using TMPro;

public class PetUI : MonoBehaviour
{
    [SerializeField] private Pet pet;
    [SerializeField] private Slider hungerBar;
    [SerializeField] private TMP_Text statusText;

    private void Start()
    {
        pet.OnStatChanged += UpdateUI;
        UpdateUI();
    }

    private void UpdateUI()
    {
        hungerBar.value = pet.Hunger;
        statusText.text = pet.Alive ? "Happy" : "Not looking good...";
    }
}

pet.OnStatChanged += UpdateUI; subscribes UpdateUI to Pet's event — from that point on, every time Pet calls OnStatChanged?.Invoke(), UpdateUI runs automatically. Drag your Pet, Slider and TextMeshPro references into the Inspector fields. Test it — every action should now visibly move the bar and update the text, with no other script touching the UI directly.

🔍 Evaluation

For each test where the actual result didn't match the expected result, write:

  1. What went wrong (the bug)
  2. What you changed to fix it (the fix)
  3. Whether the fix introduced any new problems (a regression)

A common bug at this stage: the UI never updates at all, because pet.OnStatChanged += UpdateUI; was never called — check that this line is actually inside Start() in PetUI.cs, and that the Pet reference is assigned in the Inspector, not left empty.
