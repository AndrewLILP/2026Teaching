Your First Pet Subclass

Sprint 1 gave PixelPals one solid base class. This sprint proves it was worth building properly — your first pet type inherits every field, every method, every guard clause, without retyping a single line. C# has one extra rule Godot never had: a method can only be overridden if its base class explicitly allows it. That's today's real new idea.

Producing & Implementing

Sprint 2 — Five Steps

Work through these steps in order. Test after each one — don't move on until the current step behaves correctly.

1
Duplicate the Pet Prefab
Scene Setup

Duplicate your Pet prefab in the Project panel, rename the copy Dog, and swap its model for a different curated asset. Duplicate its Canvas too — you'll add a new bar to it shortly.

You're duplicating the prefab here, not the code — the script is next.

2
Prepare Pet.cs for Extension
virtual

Unlike GDScript, C# doesn't let a subclass override any method by default — the base class has to explicitly grant permission with the virtual keyword. Open Pet.cs and make two small changes:

// Change this:
public void Play() { /* ... */ }

// To this:
public virtual void Play() { /* ... */ }

// And add this new protected helper, so subclasses can raise the event too:
protected void NotifyStatChanged()
{
    OnStatChanged?.Invoke();
}

The second change matters for a subtler reason: C# events can only be invoked from inside the class that declares them. Even though Dog inherits OnStatChanged, it can't call OnStatChanged?.Invoke() directly — only Pet can. NotifyStatChanged() is a small public doorway around that rule, exactly like the read-only properties you built in Sprint 1.

3
Create Dog.cs — Extending Pet
Inheritance

Remove the old Pet.cs from the Dog GameObject and attach a new script, saved as Dog.cs. In C#, inheritance is written with a colon:

Structured English 
CLASS Dog INHERITS Pet
  loyalty

  FUNCTION Fetch()
    IF NOT alive THEN
      RETURN
    END IF
    SET loyalty TO loyalty + 15, max 100
    EMIT StatChanged
C# 
public class Dog : Pet
{
    [SerializeField] private int loyalty = 50;

    public void Fetch()
    {
        if (!Alive) return;
        loyalty = Mathf.Min(100, loyalty + 15);
        NotifyStatChanged();
    }
}

Notice Fetch() checks Alive — the public property from Sprint 1, not the private field directly, since alive itself stays private even from Dog. : Pet means Dog automatically has every field, property and method Pet already defines — Feed(), Clean(), Hunger, all of it, before you've written a single line.

4
Override Play()
override

Add this to Dog.cs:

public override void Play()
{
    base.Play();
    loyalty = Mathf.Min(100, loyalty + 5);
}

override is the other half of the deal — it's only legal here because Pet marked Play() as virtual in Step 2. base.Play() runs Pet's original Play() first — guard clause, social increase, event notification, all of it — and only then does Dog's extra loyalty line run underneath it.

Test it — click Play on your Dog. Both social and loyalty should increase from the one click.

5
Wire the Fetch Button & Loyalty Bar
UI Binding

Add a FetchButton and LoyaltyBar to Dog's Canvas. Wire FetchButton's On Click () to Dog > Fetch() in the Inspector, the same way you wired Play/Clean in Sprint 1.

In PetUI.cs, change private void UpdateUI() to protected virtual void UpdateUI(), then create DogUI.cs:

public class DogUI : PetUI
{
    [SerializeField] private Slider loyaltyBar;
    [SerializeField] private Dog dog;

    protected override void UpdateUI()
    {
        base.UpdateUI();
        loyaltyBar.value = dog.Loyalty;
    }
}

You'll need a public int Loyalty => loyalty; property on Dog too, exactly like Hunger on Pet. Attach DogUI to Dog's Canvas instead of PetUI, and wire its references in the Inspector.

Test it — click Fetch and confirm only the Loyalty bar moves. Click Feed, Play and Clean and confirm every bar, including Loyalty from Step 4's override, still updates correctly.

🔍 Evaluation

For each test where the actual result didn't match the expected result, write:

  1. What went wrong (the bug)
  2. What you changed to fix it (the fix)
  3. Whether the fix introduced any new problems (a regression)

A common bug at this stage: Play() only increases loyalty, not social, because base.Play() was left out of the override entirely. If Test 2 fails this way, check that base.Play() is the very first line inside Dog's Play().
