Your Brief

Before Lesson 7, PixelPals needs to see every action your player can take, written out in full, plus the one thing that makes your pet worth pitching over anyone else's."

So far your pseudocode has covered single threshold reactions in isolation. A real pet system runs several things at the same time: the player can act whenever they choose, while the game itself keeps ticking along in the background. Planning both together, and getting the order right, is what today is about.

Researching & Planning

Event-Driven vs Continuous

Your pet's logic runs in two different rhythms at once. Event-driven logic only runs when something specific happens — the player pressing Feed, Play or Sleep. Continuous logic runs constantly in the background, with or without the player doing anything — the drift loop that slowly lowers hunger and energy over time.

Event-Driven

Runs only when the player presses a button — Feed, Play, Sleep

+
Continuous

Runs constantly in the background — the forever drift loop

→
Combined State

The pet's attributes at any moment reflect both at once

Why this matters for planning If you only plan the event-driven actions, your pet will feel static — nothing changes unless the player acts. If you only plan the continuous drift, the player has no way to help their pet. Every attribute in your brief needs at least one event-driven action and the continuous drift working against each other — that tension is what makes the game worth playing.

Pseudocode for the Full Loop

Here's a complete plan for one attribute, hunger, showing both rhythms together. Notice the two sections are written separately — they don't run inside each other, they run alongside each other.

Worked Example — Hunger, Fully Planned

BEGIN

  // Event-driven: runs only when the player presses Feed
  WHEN Feed button pressed
    SET hunger TO hunger + 20
    IF hunger > 100 THEN
      SET hunger TO 100
    ENDIF
    UPDATE stat display

  // Continuous: runs constantly, regardless of player input
  REPEAT FOREVER
    WAIT 5 seconds
    SET hunger TO hunger − 1
    IF hunger < 0 THEN
      SET hunger TO 0
    ENDIF
    IF hunger ≤ 0 THEN
      SET gameState TO "gameOver"
    ENDIF
  ENDREPEAT

END

Two things to notice: the IF hunger ≤ 0 lose-condition check lives inside the continuous loop, not the event-driven action — because hunger can reach 0 either from drifting down over time or from the player simply not feeding the pet often enough, and the game needs to catch both. Comments (the lines starting with //) aren't executed — they're notes for your future self, explaining why a section exists.

Researching & Planning

Choose Your Custom Stat

Every pet in this studio shares the same three core stats — your custom stat is what makes yours yours. Pick one from the four options below.

Cleanliness Standalone

Drops slowly over time. A Wash action restores it. When it's very low, the sprite looks visibly grubby and happiness drifts down faster.

Interaction: mild — affects happiness's drift rate only.

Social Standalone

Drops when the pet is left alone for a while. A Visit Friend action restores it, on a short cooldown timer so it can't be spammed.

Interaction: mild — introduces a cooldown, a new pattern you haven't used yet.

Curiosity Standalone

Rises with a new Explore action rather than falling over time. High curiosity unlocks a bonus animation or sprite variant.

Interaction: mild — the only stat in this list that rises by default instead of falling.

Health Systems Thinking

Doesn't have its own player action. Instead it falls automatically whenever hunger or energy stay critically low for too long, and is restored by a Vet action.

Interaction: strong — the only option that reacts to your other stats rather than standing alone. Best choice if you want to demonstrate systems thinking clearly.

Why Health is flagged, not required Cleanliness, Social and Curiosity are each self-contained — good, testable choices that add variety without much extra complexity. Health is different: it only exists because your other stats exist, which is exactly the systems-thinking idea from Lesson 1–2 (attributes influencing each other, not just the player). Choose it if you're ready for a slightly harder plan; choose any of the other three if you'd rather keep this World's build simpler.
Researching & Planning

Planning Its Interaction

Whichever stat you chose, it needs the same two-part treatment as your core three: an event-driven action, and a continuous rule. If you chose Health, the "event" is different — it's triggered by another stat's threshold, not a button press.

Worked Example — Health (if you chose the systems-thinking option)

BEGIN

  // Event-driven: runs only when the player presses Vet
  WHEN Vet button pressed
    SET health TO health + 30
    IF health > 100 THEN
      SET health TO 100
    ENDIF

  // Continuous: reacts to OTHER stats, not player input directly
  REPEAT FOREVER
    WAIT 5 seconds
    IF hunger ≤ 10 OR energy ≤ 10 THEN
      SET health TO health − 5
      IF health < 0 THEN
        SET health TO 0
      ENDIF
    ENDIF
  ENDREPEAT

END

CPD Grade Descriptors — Stage 5

These are the NESA Course Performance Descriptors for Stage 5 Computing Technology, used to report your achievement at the end of Year 10. Stage 4 work (Years 7–8) is pitched toward these same descriptors, adjusted for your year level. They apply across every lesson in Pet Lab — not just this one. Tap a grade to expand it.

A

Demonstrates an extensive understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; skilfully applies appropriate iterative processes to produce computing solutions; develops highly effective computing solutions using computational, design and systems thinking skills; selects and applies safe, secure and ethical practices in the use of data; skilfully develops, tests and implements technically concise algorithms in a general-purpose programming language; demonstrates creativity and innovation in the design and implementation of user interfaces to create engaging user experiences; selects relevant data, media and processes to effectively communicate information in a range of contexts.

B

Demonstrates a thorough understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; applies appropriate iterative processes to produce computing solutions; develops effective computing solutions using computational, design and systems thinking skills; selects and applies safe, secure and ethical practices in the use of data; develops, tests and implements functional algorithms in a general-purpose programming language; demonstrates creativity in the design and implementation of user interfaces to create engaging user experiences; selects relevant data, media and processes to communicate appropriate information in a range of contexts.

C

Demonstrates a sound understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; applies iterative processes to produce computing solutions; develops sound computing solutions using computational, design and systems thinking skills; applies safe, secure and ethical practices in the use of data; develops common algorithms and implements them in a general-purpose programming language; designs and implements user interfaces to create user experiences; selects appropriate data, media and processes to communicate information in a range of contexts.

D

Demonstrates a basic understanding of the influence of enterprise and innovation on the evolution of computing technology; uses processes to produce computing solutions; develops basic computing solutions using computational or design or systems thinking skills; uses data safely and responsibly; develops basic algorithms and/or implements them in a general-purpose programming language; implements basic elements of user interface design to support user experiences; uses data to communicate basic information.

Identifies the evolution of, and/or innovations in, computing technology; identifies processes that may produce a computing solution; works safely with data; follows algorithms and/or partially implements them in a general-purpose programming language; identifies elements of user interfaces that contribute to user experiences; uses data to communicate information in a very limited way.
