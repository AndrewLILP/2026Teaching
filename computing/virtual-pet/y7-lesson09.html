Feed & Play Actions

Your on start script sets the scene, but nothing changes yet without the player. Lesson 9 builds the Feed action — the simplest possible event, changing one stat. Lesson 10 builds Play, which is more interesting: it changes two stats at once, in opposite directions. That single design choice is where your pet stops feeling like a spreadsheet and starts feeling like it needs real decisions from the player.

Your Brief

Studio memo: "Two actions today, tested one at a time. Don't build Play until Feed is confirmed working — if something breaks later, you want to know exactly which action caused it. A pet with two half-working actions is much harder to debug than one with one action fully working."

You don't have a real stat display yet — that's Lesson 13. For now, you'll use a temporary debugging trick: making your sprite say its current value on screen, just long enough to confirm each action is working before you move on.

Producing & Implementing

Two Actions, Two Jobs

Both Feed and Play are event-driven, exactly like the pattern from Lesson 5–6 — each one only runs when its button is pressed. In MakeCode Arcade, controller buttons already have dedicated event blocks: on button A pressed and on button B pressed. You'll bind Feed to A and Play to B.

Why bind different actions to different buttons If Feed and Play shared a button, the game would need extra logic just to work out which action the player meant — adding complexity that has nothing to do with your pet's actual design. One button per action keeps each event block simple, self-contained, and easy to test in isolation.
Producing & Implementing

Building the Feed Action

Your Notebook Pseudocode 
WHEN Feed button pressed
  SET hunger TO hunger + 20
  IF hunger > 100 THEN
    SET hunger TO 100
  END IF
Feed Action Blocks
on button A pressed change hunger by 20 set hunger to Math.min(100, hunger) mySprite.say(hunger, 1)
STEP 1 Add the event block
From the Controller category, drag out on button A pressed onto an empty part of the canvas — separate from your on start block.
STEP 2 Change and clamp hunger
From Variables, add change hunger by 20 inside the event block. Underneath it, add set hunger to and drop in a Math.min(100, hunger) block from the Math category — this is the exact clamp pattern from Lesson 1–2, now doing real work.
STEP 3 Add a temporary debug output
From the Sprite category, add mySprite.say(hunger, 1) as the last block — it shows the current hunger value in a speech bubble for one second. You'll delete this block in Lesson 13 once a real stat display exists.
Producing & Implementing

Testing the Feed Action

Test It Now

Press Play. Press button A once — the speech bubble should show 70 (starting value 50, plus 20). Press A again — it should show 90. Press it a third time — watch closely: it should show 100, not 110. If you see a number above 100, your clamp block isn't wired correctly; recheck Step 2 before continuing.

Producing & Implementing

Building the Play Action

Play does more than Feed — it changes two stats in opposite directions, so it needs two clamps, not one.

Your Notebook Pseudocode 
WHEN Play button pressed
  SET happiness TO happiness + 15
  IF happiness > 100 THEN
    SET happiness TO 100
  END IF
  SET energy TO energy − 10
  IF energy < 0 THEN
    SET energy TO 0
  END IF
Play Action Blocks
on button B pressed change happiness by 15 set happiness to Math.min(100, happiness) change energy by −10 set energy to Math.max(0, energy) mySprite.say(happiness, 1)

Your Turn

Build the Play action using the pattern above — on button B pressed, two changes, two clamps (one Math.min for the upper limit, one Math.max for the lower limit), and a temporary say() block. Test it exactly like you tested Feed: press B repeatedly and confirm happiness stops at 100 and energy stops at 0.

Producing & Implementing

The Trade-off

Feed only ever helps hunger. Play is different — it helps happiness but costs energy. That's a deliberate design decision, not a side effect: a player who spams Play to keep happiness high will run energy down fast, and will need Sleep (Lesson 11) to recover it. No single action fixes everything at once.

Trade-offs as a systems-thinking idea A pet where every action only helps is a pet with no real decisions in it — the player would just press one button forever. Designing at least one action with a cost, not just a benefit, is what turns three independent numbers into an interacting system the player actually has to manage.
