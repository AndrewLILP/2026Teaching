Sleep & the Forever Loop

Lesson 11 finishes your set of three event-driven actions with Sleep. Lesson 12 is the most important build in this World: the forever loop that makes hunger, energy and happiness drift on their own, and checks your lose condition continuously in the background. Once this loop is running, your pet needs you even when you're doing nothing — which is the whole point of a virtual pet.

Producing & Implementing
Producing & Implementing

Your Brief

Studio memo: "The forever loop is the one piece of code every other part of your pet depends on. Build it carefully, test it patiently — five seconds feels slow when you're waiting to see a number change, but rushing this block is the single most common cause of a broken pitch."

Reminder from Lesson 7–8: hunger represents how fed your pet is. Feed raises it, the forever loop lowers it over time, and it hitting 0 means your pet has gone unfed for too long — that's the direction every block below follows.

Producing & Implementing

Building the Sleep Action

Buttons A and B are already taken by Feed and Play, so Sleep binds to a directional button instead — on button up pressed. Sleep is also your first action with a genuine cost even though it's mostly a benefit: it restores energy, but costs a small amount of hunger, since resting doesn't feed your pet.

Your Notebook Pseudocode 
WHEN Sleep button pressed
  SET energy TO energy + 30
  IF energy > 100 THEN
    SET energy TO 100
  END IF
  SET hunger TO hunger − 5
  IF hunger < 0 THEN
    SET hunger TO 0
  END IF
Sleep Action Blocks
on button up pressed change energy by 30 set energy to Math.min(100, energy) change hunger by −5 set hunger to Math.max(0, hunger) mySprite.say(energy, 1)

Your Turn

Build the Sleep action using the pattern above. Notice it follows exactly the same shape as Play — two changes, two clamps — just with different numbers and a different button. If your brief gave Sleep different values, use those instead of 30 and 5.

Producing & Implementing

Testing the Sleep Action

Test It Now

Press Play. Press the up button once — energy should rise from 50 to 80, and hunger should quietly drop from 50 to 45 (watch the hunger variable in the debugger panel, since the speech bubble is only showing energy). Press up repeatedly until energy hits 100 and confirm it doesn't go higher.

Producing & Implementing

Building the Forever Loop

This is the block your entire pet has been designed around since Lesson 1–2. It runs continuously, lowers all three core stats a little every five seconds, and checks your lose condition — all in one place.

Your Notebook Pseudocode 
REPEAT FOREVER
  WAIT 5 seconds
  SET hunger TO hunger − 1
  IF hunger < 0 THEN
    SET hunger TO 0
  END IF
  SET energy TO energy − 1
  IF energy < 0 THEN
    SET energy TO 0
  END IF
  SET happiness TO happiness − 1
  IF happiness < 0 THEN
    SET happiness TO 0
  END IF
  IF hunger ≤ 0 THEN
    SET gameState TO "gameOver"
  END IF
END REPEAT
Forever Loop Blocks
forever pause 5000 ms change hunger by −1 set hunger to Math.max(0, hunger) change energy by −1 set energy to Math.max(0, energy) change happiness by −1 set happiness to Math.max(0, happiness) if hunger ≤ 0 then set gameState to "gameOver"
STEP 1 Add the forever block
From the Loops category, drag a fresh forever block onto an empty part of the canvas — a separate block from on start, on button A pressed and the others. Inside it, add pause (ms) 5000 from Loops as the very first block.
STEP 2 Drift the three core stats
Underneath pause, add three change [stat] by −1 blocks, one for hunger, one for energy, one for happiness — each immediately followed by its own set [stat] to Math.max(0, [stat]) clamp. Six blocks in total, in three matching pairs.
STEP 3 Add the lose-condition check
From Logic, add an if hunger ≤ 0 then block as the last thing inside forever. Inside it, add set gameState to "gameOver" from Variables. This doesn't end the game yet — that's Lesson 17–18 — it just raises the flag the moment it becomes true.

Your Turn

If you chose a standalone custom stat (Cleanliness, Social or Curiosity), add its own drift pair here, following the same change-then-clamp pattern. If you chose Health, its logic is different — a reaction to hunger and energy, not a direct drift — so build it from your Lesson 5–6 Health pseudocode instead of copying this pattern directly.

Producing & Implementing

Testing the Full Loop

Test It Now — Two Checks

Check 1, the drift: press Play and don't touch any button. Watch hunger in the debugger panel — it should drop by 1 roughly every 5 seconds. If it's not moving at all, your forever block probably isn't connected to the pause block correctly.

Check 2, the lose condition: this one takes patience — at 1 per 5 seconds, hunger takes over four minutes to fall from 50 to 0. Rather than waiting, temporarily change your on start block so hunger starts at 3 instead of 50, run the game, and confirm gameState switches to "gameOver" within about 15 seconds. Change the starting value back to 50 once you've confirmed it works.

Producing & Implementing

Why the Loop Runs Separately

You now have four separate top-level blocks on your canvas: on start, on button A pressed, on button B pressed, on button up pressed, and forever. None of them are nested inside each other — they all run independently, and MakeCode Arcade manages when each one fires. This is the event-driven-plus-continuous split from Lesson 5–6, now fully real: your actions wait for the player, and the loop never waits for anyone.

Why this matters for testing Because these blocks are independent, a bug in Play can't break Feed, and a bug in the forever loop can't break either action — but it also means each one needs testing on its own, exactly like you did with Feed and Play in Lesson 9–10. You'll get a dedicated pass at testing everything together in Lessons 15–18.
