Status Display & Your Custom Stat

Every action so far has relied on a speech bubble that vanishes after one second — useful for building, useless for actually playing. Lesson 13 replaces every mySprite.say() block with a permanent on-screen readout, and makes the sprite itself change appearance when something needs attention. Lesson 14 finishes whichever custom stat you chose back in Lesson 5–6. After this page, every mechanic in your brief exists as working blocks.

Your Brief

Studio memo: "A pitch with invisible stats isn't a pitch PixelPals can evaluate. By the end of today, every attribute in your brief needs to be visible on screen at all times, and your pet's sprite needs to visibly react when something is wrong — not just internally track a number nobody can see."

Producing & Implementing

Meet game.onUpdate()

Your forever loop waits 5 seconds between each cycle — perfect pacing for stats drifting slowly, but far too slow for a status display, which needs to feel instant. game.onUpdate() is a different kind of continuous block: it runs its contents roughly 20 times every second, with no pause needed.

Two loops, two jobs forever + pause 5000ms Slow, deliberate changes — drift, thresholds, anything that should feel gradual. game.onUpdate() Fast, constant checks — anything the player needs to see respond immediately, like a number on screen or a sprite's appearance.

Building the Status Display

You'll print all four attributes — three core stats plus your custom stat — as small text in the corner of the screen, refreshed every frame.

H: 70
E: 80
Ha: 45
Cu: 60
Your Notebook Pseudocode 
REPEAT FOREVER (every frame)
  SHOW hunger at position (4, 4)
  SHOW energy at position (4, 14)
  SHOW happiness at position (4, 24)
  SHOW [customStat] at position (4, 34)
END REPEAT
Status Display Blocks
game.onUpdate screen.print("H:" + hunger, 4, 4, 1) screen.print("E:" + energy, 4, 14, 1) screen.print("Ha:" + happiness, 4, 24, 1) screen.print("Cu:" + customStat, 4, 34, 1)
STEP 1 Add game.onUpdate
From the Game category, drag game.onUpdate onto an empty part of the canvas — a fifth top-level block, separate from everything else.
STEP 2 Print each attribute
From Scene, add four screen.print blocks inside game.onUpdate. Join the label text and the variable together using the join block from Text (for example, joining "H:" with hunger) so each line reads clearly. Give each line a different y-position, ten pixels apart, so they don't overlap.

Making the Sprite React

Back in Lesson 7–8 you drew one costume for your pet. Now draw a second, "struggling" costume — and swap between them automatically based on hunger, right inside the same game.onUpdate block.

Your Turn

Click your sprite block's image thumbnail to draw a second costume — visibly different, like closed eyes or a frown. In Variables, create a new variable called sadCostume and set it to that image using set sadCostume to sprite inside on start. Then, inside game.onUpdate, add an if hunger < 20 then / else block: when true, set mySprite's image to sadCostume; when false, set it back to the original.

Why this belongs in onUpdate, not the forever loop If this check only ran once every 5 seconds, the sprite could stay in the wrong costume for up to 5 seconds after hunger recovers — a small but noticeable lag. Visual feedback needs the fast loop; numeric drift doesn't.

Finishing Your Custom Stat

If you haven't already built your custom stat's blocks, do it now — here's a fully worked example for Curiosity, the one curated option that behaves differently from every other stat.

Curiosity Pseudocode 
WHEN Explore button pressed
  SET curiosity TO curiosity + 25
  IF curiosity > 100 THEN
    SET curiosity TO 100
  END IF

// inside game.onUpdate, not forever —
// curiosity doesn't decay, only reacts
IF curiosity >= 80 THEN
  SHOW bonus sprite variant
END IF
Curiosity Blocks
on button down pressed change curiosity by 25 set curiosity to Math.min(100, curiosity) if curiosity ≥ 80 then set mySprite's image to bonusCostume
Notice what's missing There's no drift pair for curiosity in the forever loop — by design, from Lesson 5–6, it only ever changes through its own action. Not every attribute needs the full two-part treatment; curiosity is proof that a plan can deliberately leave one half out.

If You Chose a Different Stat

Cleanliness or Social: follow the exact two-part hunger pattern from Lesson 1–2 and Lesson 9–10 — an event action plus a drift pair in the forever loop, both clamped. Health: follow the dependent pattern already fully worked in Lesson 5–6 and Lesson 11–12 — a Vet action, plus a check inside the forever loop that reacts to hunger and energy rather than decaying on its own. Either way, add your custom stat's print line to game.onUpdate if you haven't already.

These are the NESA Course Performance Descriptors for Stage 5 Computing Technology, used to report your achievement at the end of Year 10. Stage 4 work (Years 7–8) is pitched toward these same descriptors, adjusted for your year level. They apply across every lesson in Pet Lab — not just this one. Tap a grade to expand it.

Demonstrates an extensive understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; skilfully applies appropriate iterative processes to produce computing solutions; develops highly effective computing solutions using computational, design and systems thinking skills; selects and applies safe, secure and ethical practices in the use of data; skilfully develops, tests and implements technically concise algorithms in a general-purpose programming language; demonstrates creativity and innovation in the design and implementation of user interfaces to create engaging user experiences; selects relevant data, media and processes to effectively communicate information in a range of contexts.
