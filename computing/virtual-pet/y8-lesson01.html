Identifying & Defining

From Blocks to Text

Here's the exact Feed action from your Year 7 project, next to the Python that does the same job. Read both sides together — every block has a direct Python equivalent.

Year 7 — MakeCode Blocks
on button A pressed change hunger by 20 set hunger to Math.min(100, hunger)
Year 8 — Python 
def feed():
    global hunger
    hunger = hunger + 20
    hunger = min(100, hunger)

Four things map directly: the event block on button A pressed becomes a Python function, def feed():. The clamp block Math.min(100, hunger) becomes Python's own built-in min(100, hunger) — same job, same two numbers, same result. And the trigger itself moves from a physical button to a typed word, which you'll meet properly in the next section.

Why the global keyword In MakeCode, any block can freely change any variable. In Python, a variable created inside a function only exists inside that function by default — changing hunger without global hunger would create a brand new, separate variable that vanishes the moment the function ends, leaving the real hunger value untouched. global tells Python "use the one variable that lives outside this function," which is what lets feed() permanently change your pet's state.

Reading the Command Loop

Without physical buttons, the demo program needs another way to know what the player wants. It works by asking the player to type a word, then matching that word against a list of known commands.

Year 7 — Three Separate Event Blocks
on button A pressed call feed() on button B pressed call play()
Year 8 — One Loop, Checking Text 
while running:
    command = input("> ")
    if command == "feed":
        feed()
    elif command == "play":
        play()
    elif command == "quit":
        running = False

MakeCode gave you one event block per button, running automatically. Python has no equivalent for "wait for a specific key" built into the language this simply — instead, one while loop keeps asking the player to type something, and an if / elif chain checks the typed text against every command your pet understands. running is a boolean — a variable that's only ever True or False — and setting it to False is what makes the loop stop.

What happens to a command that doesn't match anything? Look again at Question 5 from the Analyse First task. An if / elif chain with no matching branch simply does nothing by default — unless the program includes a final else to catch unrecognised input and tell the player. Whether the demo has that else or not is exactly the kind of design decision worth noting for Question 7.
