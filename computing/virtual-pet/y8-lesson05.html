Functions With Parameters

The functions you read in Lesson 1–2, like feed(), took no information in and gave nothing back — they just changed a global variable directly. A function can also accept parameters (values passed in when it's called) and produce a return value (a result sent back to whoever called it).

A Function With Parameters and a Return Value

def double(number):
    result = number * 2
    return result

x = double(7)   # x is now 14

number is the parameter — a placeholder that becomes whatever value is passed in when the function is called. return result sends a value back out, which is then stored in x. Nothing here is specific to pets yet; this is a general Python pattern you'll use constantly from this point on.

Researching & Planning

One Function, Every Action

Here's the clamp logic from every one of your Year 7 actions, written once as a reusable function.

change_stat — Reusable Clamp Function

def change_stat(current_value, amount, minimum=0, maximum=100):
    new_value = current_value + amount
    if new_value < minimum:
        new_value = minimum
    if new_value > maximum:
        new_value = maximum
    return new_value

Every action now becomes a short function that calls this one instead of repeating the clamp itself:

feed — Calling change_stat

def feed():
    global hunger
    hunger = change_stat(hunger, 20)

minimum=0, maximum=100 are default values — if a call to change_stat doesn't specify them, Python uses 0 and 100 automatically, which is why feed() only needs to pass in hunger and 20. If you ever needed different limits for a specific stat, you could still override them by passing extra arguments.

Why this matters more in Python than it did in Year 7 MakeCode's clamp blocks were quick to duplicate because dragging a block costs almost nothing. Python code that's typed out by hand has a real cost to duplicating it — every repeated clamp is a place a future bug fix might get missed. One function, called from everywhere, means fixing the clamp logic once fixes it everywhere at once.

Planning the Full Command Loop

This is the complete plan for the loop you started reading in Lesson 1–2 — now with every command your pet needs, plus the lose-condition check running every cycle.

Full Command Loop Plan

while running:
    command = input("> ")

    if command == "feed":
        feed()
    elif command == "play":
        play()
    elif command == "sleep":
        sleep()
    elif command == "status":
        status()
    elif command == "quit":
        running = False
    else:
        print("I don't understand that command.")

    if hunger <= 0:
        print("Your pet is starving. Game over.")
        running = False

Two design decisions worth noticing. First, the final else catches any typed text that doesn't match a known command — something Year 7 never needed, since a physical button can only ever be exactly itself. Second, the lose-condition check sits after the command handling but still inside the loop, so it's tested every single cycle regardless of which command was typed — the same "check continuously, not just after one specific action" principle from Year 7's forever loop.
