Your Brief

Studio memo: "Same rule as every studio before this one: translate your plan, don't improvise a new one. Your Lesson 5–6 notebook already has change_stat(), your action functions and your full command loop planned out — today's job is typing exactly that, in the right order, and nothing else yet."

Python files run top to bottom. That single fact decides the order everything in your file needs to go: variables first, then function definitions, then the code that actually calls them, right at the bottom. Get the order wrong and Python will complain about something "not defined" before your program even starts.

Setting Up Your Project

Create a new Python file in your usual editor (Thonny, VS Code, or your class's tool) and save it as pet.py, using your actual pet's name in a comment at the top instead of a generic filename.

Declaring Your Variables

Unlike Year 7, there's no separate on start event — variables declared at the very top of a Python file, outside any function, run once automatically the moment the program starts.

Top of pet.py

# [Your Pet Name] — a Pet Lab project

pet_name = "[Your Pet Name]"
hunger = 50
energy = 50
happiness = 50
[customStat] = 50
game_state = "playing"
running = True

Match every value here to your Lesson 3–4 brief exactly. running is new — it's the boolean your command loop will check in Lesson 9–10, but it needs to exist now, before any function that might reference it is defined.

Producing & Implementing

Building print_status()

Your first function only ever reads your variables — it never changes a single one. That makes it the perfect first build, and a direct test of the global rule from Lesson 1–2.

print_status() — Using f-strings

def print_status():
    print(f"--- {pet_name}'s Status ---")
    print(f"Hunger: {hunger}/100")
    print(f"Energy: {energy}/100")
    print(f"Happiness: {happiness}/100")
    print(f"[CustomStat]: {[customStat]}/100")

An f-string — a text string with an f right before the opening quote — lets you drop a variable's value directly into the middle of text, inside curly braces { }. It's the Python equivalent of the join block you used to build text output back in Year 7's status display.

Notice what's missing: global print_status() reads hunger, energy and happiness but never assigns a new value to any of them — and that's exactly why it doesn't need global. Back in Lesson 1–2 you learned global is required when a function changes an outer variable; reading one works perfectly well without it. This function is proof of that rule, not an exception to it.

Run your file and confirm every value printed matches your brief's starting values exactly. If Python reports an error naming one of your variables, check that its declaration at the top of the file is spelled identically to how it's used inside print_status() — Python treats hunger and Hunger as two completely different names.
