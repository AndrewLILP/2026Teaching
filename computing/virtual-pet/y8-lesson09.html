Producing & Implementing

Boolean Return Values

A function can return a boolean — True or False — to report whether something succeeded, instead of returning a number like change_stat() does. Whatever calls the function can then check that value and react differently depending on the result.

A Minimal Example

def is_even(number):
    return number % 2 == 0

if is_even(6):
    print("Even!")

is_even(6) returns True, so the print line runs. This is the exact shape feed() and play() will follow — instead of a math check, they'll test whether the action makes sense to run at all.

Producing & Implementing

The Guard Clause Pattern

A guard clause checks for the invalid case first, right at the top of a function, and exits immediately if it's true — before any of the function's real work runs. It's called a "guard" because it stands in front of the rest of the function, refusing entry to situations that shouldn't proceed.

Shape of a Guard Clause

def some_action():
    if invalid_condition:
        return False   # guard — exit early, do nothing else

    # the real work only runs if the guard didn't trigger
    ...
    return True
Why check first, not after If a function changed values and only checked afterward whether it should have, it would need to undo those changes when the guard condition turns out to be true — messy, and easy to get wrong. Checking first means the function's real work only ever runs when it's actually valid to run, with nothing to undo.
Producing & Implementing

Building feed()

feed()'s guard condition: if hunger is already at 100, feeding would do nothing useful, so it should refuse and say so.

feed() — With a Guard Clause

def feed():
    global hunger

    if hunger >= 100:
        return False   # guard — already full

    hunger = change_stat(hunger, 20)
    return True

Notice global hunger is still needed — the guard clause only adds an early exit, it doesn't change the fact that the function assigns a new value to hunger further down.

Building play()

play() needs the same shape, with a different guard condition — and it changes two stats, exactly like Year 7's Play action did.

Your Turn

Build play() yourself, following feed()'s shape exactly. Its guard condition should check energy <= 0 — a pet with no energy left is too tired to play. If the guard doesn't trigger, it should call change_stat() twice: once to raise happiness by 15, once to lower energy by 10, then return True.

Two global variables, one function play() changes both happiness and energy, so its global line needs both names, separated by a comma: global happiness, energy. Forgetting either one is a common bug — Python won't necessarily show an error, it'll just quietly create a local variable for whichever name you missed.
