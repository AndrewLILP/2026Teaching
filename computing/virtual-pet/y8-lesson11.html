Producing & Implementing

Building sleep()

sleep()'s guard: if energy is already at 100, there's nothing to gain from resting.

sleep() — Same Shape as feed() and play()

def sleep():
    global energy, hunger

    if energy >= 100:
        return False   # guard — already fully rested

    energy = change_stat(energy, 30)
    hunger = change_stat(hunger, -5)
    return True

Two things to notice. First, hunger = change_stat(hunger, -5) is a real cost, not a bug — resting doesn't feed your pet, so a small hunger drop is the same deliberate trade-off Year 7's Sleep action had. Second, change_stat's default minimum of 0 means hunger can never go negative from this line, even without writing a separate clamp here.

Assembling the Main Loop

This is the plan from Lesson 5–6, finished — now using every action's return value to choose what to print.

Full Main Loop

while running:
    command = input("> ")

    if command == "feed":
        success = feed()
        if success:
            print("You fed your pet.")
        else:
            print("Your pet is already full.")

    elif command == "play":
        success = play()
        if success:
            print("You played with your pet.")
        else:
            print("Your pet is too tired to play.")

    elif command == "sleep":
        success = sleep()
        if success:
            print("Your pet had a nice rest.")
        else:
            print("Your pet is already fully rested.")

    elif command == "status":
        print_status()

    elif command == "quit":
        running = False

    else:
        print("I don't understand that command.")

    if hunger <= 0:
        print("Your pet is starving. Game over.")
        running = False

Every action branch follows the identical shape: call the function, store the result, then print one of two messages depending on whether it's True or False. This is the direct payoff of Lesson 9–10's work — without a boolean return value, there'd be no way to tell a wasted command from a successful one.
