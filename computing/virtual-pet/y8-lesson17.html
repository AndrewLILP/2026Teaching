Fixing the KeyError

The fix is one small change — Python lets a single except catch several exception types at once, by listing them together in parentheses.

load_game() — Updated except line

    try:
        ... unchanged ...
        return True
    except (FileNotFoundError, KeyError):
        return False   # no save yet, or save file is incomplete

Both situations — a missing file, or a file that's missing a key — should be handled the exact same way here: fall back to the starting values. Grouping them means one line of code covers both, rather than writing two nearly identical except blocks.

Building a Real End Condition

Right now, hitting the lose condition just prints one line and stops. But think about what happens next time the player runs the program: load_game() would load a pet that's already starving, with no way to know it had already lost. A real ending needs to address that.

end_game()

def end_game():
    print("=== Game Over ===")
    print_status()
    choice = input("Delete your save and start fresh next time? (yes/no) > ")

    if choice == "yes":
        try:
            os.remove("save.json")
            print("Save file deleted.")
        except FileNotFoundError:
            print("No save file to delete.")
    else:
        print("Save kept — you'll reload a game-over pet next time.")

Add import os to your imports at the top of the file, alongside import json — os.remove() is what actually deletes the file. Notice the try/except here is the same pattern again, protecting against a save file that's already gone by the time this runs.

A real design decision, not just cleanup Deleting on "yes" versus keeping on "no" is a genuine choice you're giving the player, not busywork — it's the same kind of design thinking as a win/lose condition or a trade-off action, applied to what happens after the game technically ends.

The old single print line is replaced by a call to your new, more complete function — the loop itself barely changes, since all the real behaviour now lives inside end_game() where it's easier to find and adjust later.
