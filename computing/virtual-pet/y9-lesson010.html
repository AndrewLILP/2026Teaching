Meet the Class-Based Pet

Same idea, new structure. In Year 8 you built a pet using stand-alone functions and the global keyword. This term, you'll rebuild that same idea using a class — a blueprint that bundles your pet's data and its actions together in one place. Before you write a single line, you'll read a working, single-class demo and see exactly how your Year 8 functions map onto Python's class syntax.

Your Brief

Studio memo: "PixelPals wants every pet in the studio catalogue to share the same reliable core behaviour, no matter which pet type a player eventually picks. Before your team builds a whole family of pet types next lesson, prove you can read a program built around a single class. Open the attached demo, trace exactly what __init__ does, and be ready to explain how it relates to the functions you built last year."

Nothing about the design changes this term — you'll still track hunger, cleanliness, social, curiosity and health, and your pet will still respond to typed commands in a console loop. What changes is entirely how the code is organised: the variables you used to write global hunger for now live inside a class, and every action you used to write as a stand-alone function becomes a method — a function that belongs to the class and works on that class's own data.

Identifying & Defining

From Functions to Methods

Here's the exact Feed action from your Year 8 project, next to the Python that does the same job inside a class. Read both sides together — every line has a direct equivalent.

Year 8 — Function + global 
def feed():
    global hunger
    hunger = hunger + 20
    hunger = min(100, hunger)
Year 9 — Method inside a class 
class Pet:
    # ...
    def feed(self):
        self.hunger = self.hunger + 20
        self.hunger = min(100, self.hunger)

Three things map directly: the stand-alone function def feed(): becomes a Python method, written def feed(self): inside a class. The line global hunger disappears entirely — there's no shared, program-wide variable to reach out to any more. In its place, every reference to hunger becomes self.hunger, which always means "the hunger belonging to this particular pet."

Where did global go? In Year 8, hunger was one single variable shared by the whole program — global was needed so a function could reach out and change it. In Year 9, each pet object stores its own hunger as an attribute, and self is simply how a method says "the copy that belongs to me." There's nothing to reach out to any more, because the data already lives right where the method is.
Identifying & Defining

Reading the Class Structure

Here's a trimmed-down version of the full demo, showing the class definition and how one pet object is created and used. This is the shape you'll be reading in full when you open the demo file.

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 50
        self.social = 50

    def feed(self):
        self.hunger = min(100, self.hunger + 20)
        print(self.name, "was fed.")

    def play(self):
        self.social = min(100, self.social + 15)
        print(self.name, "had fun playing.")

# Creating one pet object from the Pet class
fido = Pet("Fido")
fido.feed()
fido.play()

Read this in two layers. The class Pet: block is the blueprint — it describes what every pet will have (a name, hunger, social) and what every pet can do (feed, play), but it isn't a pet itself. The line fido = Pet("Fido") is where an actual pet gets built from that blueprint: fido is an object, or an instance, of the Pet class.

__init__ is a special method that runs automatically the moment an object is created, and its job is to set up that object's starting attributes. You never call fido.__init__() yourself — writing Pet("Fido") is what triggers it. Notice too that when you call fido.feed(), you don't type the self in — Python fills it in for you, and it always refers back to fido.

One class, one pet — for now This demo only ever creates a single Pet object. Starting next lesson, you'll create several objects from the same class, and after that, build different types of pet that share this same structure but behave a little differently. Both of those ideas build directly on what you're reading here.
