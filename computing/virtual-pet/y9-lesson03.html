Write Your Y9 Pet Brief

PixelPals wants a real design document, not a vague idea. Your Pet Brief is this studio's version of a Game Design Document — six short sections that turn everything you noticed in Lessons 1–2 into a precise plan. One section, the Core Loop, needs pseudocode; the rest can stay as prose or lists. Lesson 5's base-class build follows directly from what you write here.

Identifying & Defining

Your Brief

Studio memo: "Before PixelPals takes any pitch seriously, we want a Pet Brief — six short sections, precise enough that another developer could pick it up and start building. Guessing at stats or node structure once you're mid-build is how projects fall apart. Base every decision on what you found in Lessons 1–2."

Every pet type you eventually build in this World will share one base class, so this brief is written for that base class — the pet type every future variation will build on, not one single named pet.

Identifying & Defining

Pet Brief Structure — Six Sections

Your Pet Brief needs these six sections. Keep each one short — a paragraph or a short list is enough. Depth comes later, through iteration.

1

Concept & Pitch

One sentence describing your pet type, written the way you'd pitch it to PixelPals in person. What makes it different from the starter project's pet?

2

Core Loop

The moment-to-moment cycle a player repeats — click a button, a stat changes, the UI updates, stats decay over time. This is the only section requiring pseudocode today.

3

Stat System

Three core stats with starting values, and exactly which button or Timer changes each one, and by how much.

4

Shared vs Unique

What every future pet type must share, because it lives in the base class, versus what you expect individual pet types to do differently later.

5

Win & Lose Conditions

Exactly what state counts as winning, and exactly what causes the pet to be lost. Both need to be testable — a condition you can't test isn't finished design.

6

Node/Scene Plan

A first-draft scene tree for your own pet, using the node types you learned from the starter project (AnimatedSprite2D, Area2D, Timer, and so on).

Researching & Planning

Core Loop & GDScript

Pseudocode forces every rule in your Core Loop to be specific and testable before any code exists — it's the one section that becomes GDScript directly in Lesson 5. Here's a generic pet Core Loop to model yours on:

Structured English 
WHEN FeedButton pressed
  CALL feed()

FUNCTION feed
  IF NOT alive THEN
    RETURN
  END IF
  SET hunger TO hunger + 20, max 100
  EMIT stat_changed signal
GDScript 
func _on_feed_button_pressed():
  feed()

func feed():
  if not alive:
    return
  hunger = min(100, hunger + 20)
  emit_signal("stat_changed")

Notice the full cycle: a UI signal (pressed) calls a method, the method's guard clause checks alive before doing anything, the stat changes, and a signal (stat_changed) tells the UI to update itself. This exact shape — signal in, guard clause, change state, signal out — is what every action in your own Core Loop should follow.

Base class now, subclasses in Lesson 5–6 You confirmed the mechanism already: pet types will be built with plain GDScript inheritance — class_name Dog extends Pet, one shared .gd script per type. Everything in this Core Loop belongs to the base Pet class. Don't design Dog or Cat specifics yet — that's what your Shared vs Unique section is for.

Your Turn

Write your own Core Loop as structured English pseudocode, deliberately different from the example above in at least one meaningful way — a different button, a different stat, or an extra step. Then translate it into GDScript, following the same signal → guard clause → change → signal shape.

Researching & Planning

Node/Scene Plan

Sketch a first-draft scene tree for your own pet, in your notebook, in the same style as the starter project you analysed in Lessons 1–2:

Pet (Node2D) ├─ AnimatedSprite2D // your pet's states go here ├─ ClickArea (Area2D) │   └─ CollisionShape2D ├─ StatTimer (Timer) └─ UI (CanvasLayer)    └─ // your bars and buttons go here

You don't need to change the overall shape — the starter project's structure already solves the click-detection and stat-decay problems. What's yours to design is what sits inside AnimatedSprite2D (which mood states exist) and what sits inside UI (which bars and buttons your pet actually needs).

CPD Grade Descriptors — Stage 5

These are the NESA Course Performance Descriptors for Stage 5 Computing Technology, used to report your achievement at the end of Year 10. They apply across every lesson in Pet Lab — not just this one. Tap a grade to expand it.

A

Demonstrates an extensive understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; skilfully applies appropriate iterative processes to produce computing solutions; develops highly effective computing solutions using computational, design and systems thinking skills; selects and applies safe, secure and ethical practices in the use of data; skilfully develops, tests and implements technically concise algorithms in a general-purpose programming language; demonstrates creativity and innovation in the design and implementation of user interfaces to create engaging user experiences; selects relevant data, media and processes to effectively communicate information in a range of contexts.

B

Demonstrates a thorough understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; applies appropriate iterative processes to produce computing solutions; develops effective computing solutions using computational, design and systems thinking skills; selects and applies safe, secure and ethical practices in the use of data; develops, tests and implements functional algorithms in a general-purpose programming language; demonstrates creativity in the design and implementation of user interfaces to create engaging user experiences; selects relevant data, media and processes to communicate appropriate information in a range of contexts.

C

Demonstrates a sound understanding of the influence of enterprise, innovation and automation on the evolution of computing technology; applies iterative processes to produce computing solutions; develops sound computing solutions using computational, design and systems thinking skills; applies safe, secure and ethical practices in the use of data; develops common algorithms and implements them in a general-purpose programming language; designs and implements user interfaces to create user experiences; selects appropriate data, media and processes to communicate information in a range of contexts.

D

Demonstrates a basic understanding of the influence of enterprise and innovation on the evolution of computing technology; uses processes to produce computing solutions; develops basic computing solutions using computational or design or systems thinking skills; uses data safely and responsibly; develops basic algorithms and/or implements them in a general-purpose programming language; implements basic elements of user interface design to support user experiences; uses data to communicate basic information.

E

Identifies the evolution of, and/or innovations in, computing technology; identifies processes that may produce a computing solution; works safely with data; follows algorithms and/or partially implements them in a general-purpose programming language; identifies elements of user interfaces that contribute to user experiences; uses data to communicate information in a very limited way.
