Your First Pet Subclass

Sprint 1 gave PixelPals one solid base class. This sprint proves it was worth building properly: your first pet type inherits everything — every attribute, every method, every guard clause — without you retyping a single line. Then you'll add exactly one thing that's unique to this pet type, and override one inherited method to behave slightly differently. This is extends doing real work.

Producing & Implementing

Sprint 2 — Five Steps

Work through these steps in order. Test after each one — don't move on until the current step behaves correctly.

1
Duplicate the Pet Scene
Scene Setup

Right-click your Pet.tscn scene in the FileSystem panel and choose Duplicate. Rename the copy Dog.tscn, and rename its root node from Pet to Dog. Swap the AnimatedSprite2D's artwork for whatever this pet type actually looks like.

You're duplicating the scene here, not the code — the script is next.

2
Create Dog.gd — Extending Pet
Inheritance

Remove the old Pet.gd script from the Dog root node and attach a brand-new script, saved as Dog.gd. Its very first two lines do all the work:

Structured English 
CLASS Dog INHERITS Pet
  // nothing new yet — Dog already
  // has everything Pet has
GDScript 
class_name Dog
extends Pet

Test it — run the Dog scene right now, before adding anything else. Feed, Play and Clean should all work exactly as they did on the base Pet, because Dog has inherited every attribute and every method automatically.

3
Add One Unique Attribute & Method
Extending

Now add what's actually unique to this pet type, from your Shared vs Unique plan. Below extends Pet, add a new attribute and a new method — following the exact same guard-clause shape every method in Pet already uses:

Structured English 
CLASS Dog INHERITS Pet
  loyalty

  FUNCTION fetch
    IF NOT alive THEN
      RETURN
    END IF
    SET loyalty TO loyalty + 15, max 100
    EMIT stat_changed signal
GDScript 
class_name Dog
extends Pet

var loyalty: int = 50

func fetch():
  if not alive:
    return
  loyalty = min(100, loyalty + 15)
  emit_signal("stat_changed")

loyalty and fetch() exist only on Dog — the base Pet class, and any other pet type you build later, never sees them. That's exactly what "unique" meant in your Shared vs Unique plan.

4
Override an Inherited Method
Overriding

Sometimes a pet type needs to do something extra during a method it already inherited, without rewriting that method from scratch. Add this to Dog.gd:

func play():
  super.play()
  loyalty = min(100, loyalty + 5)

Writing func play(): again inside Dog overrides Pet's version — when you call play() on a Dog, this new version runs instead. super.play() is the key line: it runs Pet's original play() first — guard clause, social increase, signal emit, all of it — and only then does Dog's extra loyalty line run underneath it. You haven't rewritten Pet's logic; you've built on top of it.

Test it — click Play on your Dog. Both social and loyalty should increase from the one click.

5
Wire the Fetch Button & Loyalty Bar
UI Binding

Add a FetchButton and a LoyaltyBar to Dog's UI node — these exist only on the Dog scene, not on the base Pet. Connect FetchButton's pressed signal to a new _on_fetch_button_pressed() function calling fetch().

Then override _update_ui() the same way you overrode play(), so the Loyalty bar updates alongside every inherited bar:

func _update_ui():
  super._update_ui()
  $UI/LoyaltyBar.value = loyalty

Test it — click Fetch and confirm only the Loyalty bar moves. Click Feed, Play and Clean and confirm every bar — including Loyalty, from Step 4's override — still updates correctly.

🔍 Evaluation

For each test where the actual result didn't match the expected result, write:

  1. What went wrong (the bug)
  2. What you changed to fix it (the fix)
  3. Whether the fix introduced any new problems (a regression)

A common bug at this stage: play() only increases loyalty, not social, because super.play() was left out of the override entirely. If Test 2 fails this way, check that super.play() is the very first line inside Dog's play(), not missing or placed after the loyalty change.
